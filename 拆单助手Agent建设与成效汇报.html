拆单助手 Agent 建设与成效汇报

项目背景
业务现状
动销订单来源于 Shopify
国内发货商品先采购回自有仓库，使用第三方 SaaS 系统易仓承接入库和出库流程
商品来源多元化：供应商商品（国内发货 + 海外代发 + 国内代发）/ 其他平台海外代发（CJ、Trendsi、等）
业务痛点
订单商品仓发地不同，均需人工一单一单手动拆单才能履约，效率极低
拆单规则复杂：先按国内 / 海外拆，海外再按供应商拆，多维度叠加
国内订单需按到仓时间拆单：创建 X 天后检查入库状态，已入仓先发，避免整单等待
海外代发全靠线下表格人工流转，易出错，难追溯；易仓不支持以上规则自动处理
项目目标
项目目标
按仓发地（国内 / 海外）和供应商自动分组拆单，替代人工线下表格流转
超期未入仓订单按易仓实时库存自动触发二次拆单，已入仓先发，减少等待
订单数据异常或系统故障，自动推送钉钉告警，无需人工轮询排查
预售、POD、海外转国内等复杂场景，ERP 页面支持人工手动拆单兜底

Agent & ERP 能力

Agent — 结构和能力

① 触发层 Agent 怎么"醒"
钉钉 @机器人 — 人工触发，即时响应 Cron 定时轮询 — 每 10 分钟自动巡检 事件触发 — 拆单完成后自动触发易仓同步
② 感知层 Agent 怎么"看"
poll_split_queue — 轮询待处理订单队列 get_split_context — 获取订单详情与发货单上下文
③ 决策层 Agent 怎么"想" 只负责"想"，不负责"做"
规则判断 — 按 warehouseType + supplierId 决定分组策略，缺值自动拦截
拆单决策 — 判断是否需要拆单、拆成几笔、按什么维度拆
二次拆分 — 超 7 天未履约子单，按易仓实时库存判断是否二次拆分
发货拉取决策 — 判断 WAITING_FULFILL 订单是否已从易仓发货，决定是否拉取单号
④ 执行层 Agent 怎么"做" MCP 工具 · 纯执行，不含业务逻辑
execute_split_order — 执行拆单并下发至履约平台 pull_domestic_fulfillment — 拉取易仓发货单号并回填 stock_resplit — 按库存执行二次拆分
⑤ 保障层 Agent 怎么"稳"
主动故障告警 — 后端 403/500 或订单商品数据异常时，自动推送钉钉群，附带错误码与日志片段
版本控制 — Git Tag 语义化版本管理，输出标注环境 + 版本号
多环境隔离 — OFP_ENV 环境变量切换 QA / Prod，API Key 安全注入
操作日志 — 完整记录时间 + 操作人 + 内容，可追溯
💡 为什么这样拆？
传统模式
规则变更 → 改代码 → 发版本 → 功能回归测试 → 上线
周期长 · 成本高 · 风险大
Agent + MCP 模式
规则变更 → 改 Agent 规则 + 测试 → 上线
无需改代码 · 无需发版本
前提：新增规则所需字段已有，无需新增字段查询
✓ 规则 Agent 化，适应度高 ✓ 决策与执行分离，职责清晰 ✓ 规则变更 = 配置变更，非代码变更 ✓ 上线周期大幅缩短

ERP 迭代 — 能力

拆单结果展示 — Agent 拆单结果按分组可视化呈现，支持查看每笔子单明细
手动拆单 — 预售、POD、海外转国内等特殊场景，页面支持人工手动拆单兜底
标记发货 — 页面手动标记发货/批量导入发货，处理 Agent 未覆盖的场景
操作日志 — 完整记录时间 + 操作人 + 内容，所有操作可追溯
手动拆单涉及 Shopify + OFP + 易仓 3 平台 · 8 个 API 链式调用

Agent 自动拆单流程

订单进入待处理队列后，Agent 每 10 分钟自动巡检并完成拆单

前置条件
订单履约平台接收 Shopify 订单后，写入待处理队列，状态标记为"待处理"
1
拉取待处理订单
从待处理队列中筛选所有"待处理"状态的订单，逐笔遍历
2
查询订单详情
根据订单号向 Shopify 查询完整的发货单信息
3
校验发货单状态
检查每张发货单的状态，可处理的进入下一步，已关闭/已发货的跳过并记录
4
判断是否需要拆单
海外仓多供应商混合 → 拆分 单一类型 → 直接记录
5
执行拆单并回写结果
调用 Shopify 拆单接口完成拆分，将拆单结果写回订单履约平台（支持页面查看、手动拆单、手动标记发货）
6
标记处理结果
✓ 成功 → 标记"已处理" ✗ 失败 → 记录重试，保持"待处理"
7
异常告警
同一订单失败超过 3 次 → 标记为"失败"，推送钉钉告警，附带错误详情

同步易仓及发货状态回传

拆单完成后，国内仓订单自动同步易仓；Agent 定时监听发货状态，获取物流单号并回写 Shopify

阶段一 同步易仓 拆单完成后自动触发
1
获取国内仓子订单
拆单完成后，Agent 自动获取拆分出的国内仓子订单列表
2
同步订单至易仓
调用易仓同步接口，推送订单信息及商品明细
3
记录同步状态
子订单标记为"已同步"，同时记录易仓订单号，便于后续追踪
4
易仓处理发货
订单进入易仓标准流程：入库 → 出库 → 发货
阶段二 发货状态回传 Agent 定时任务 · 每 10 分钟
5
查询易仓发货状态
定时向易仓查询订单列表，筛选已发货的订单
6
匹配履约平台子订单
通过订单号将易仓发货信息与履约平台中的子订单进行匹配
7
提取物流信息
从易仓返回数据中提取物流单号和物流公司
8
更新履约平台状态
子订单标记为"已发货"，写入物流单号和物流公司
9
回写 Shopify 物流信息
调用 Shopify 发货接口，将物流单号和公司回写至平台
10
买家可查看物流
Shopify 订单标记为已发货，买家端实时可见物流追踪信息
同步易仓：拆单完成后自动触发（国内仓订单）
发货回传：Agent 定时任务（每 10 分钟）

经验复盘

为什么要用 Agent + ERP 迭代的方式？

手动拆单复杂度高，不适合 Agent 化
🔗
跨平台事务一致性
涉及 Shopify + OFP + 易仓，8 个 API 链式调用，任一环节失败需回滚前序操作，需 Saga / 补偿机制
🖱️
依赖 UI 交互
操作人员需在页面上点选 SKU、预览分组结果，Agent 对话式交互无法承载此类 UI 操作
⚙️
确定性编排优于 AI 推理
8 个 API 的调用顺序、超时、重试策略，后端代码实现比 Prompt 推理更可靠、更经济
ERP 迭代的长期价值
🌐
为海外仓线上化奠定基础
手动拆单沉淀的跨平台 API 调用能力（Shopify 拆单、易仓订单管理、履约数据同步），可直接复用于海外仓订单线上化场景
🏗️
拆单引擎可扩展
ERP 端沉淀的拆单引擎和平台连接层，为后续全链路自动履约（含海外仓）奠定技术基础
