# B 端产品多项目文档库

产品需求文档（PRD）、原型、知识库的统一版本管理仓库。
仓库根为**共享配置层**，业务文档**按项目分目录**存放。

## 项目列表

| 项目 | 目录 | 内容 |
|------|------|------|
| 杉缔ERP | [杉缔ERP/](杉缔ERP/) | 多平台订单管理、采购、仓储、物流、财务、报价核算；含供应商门户、供应商财务对账、易仓采购协同、自动拆单 Agent |

## 目录结构

```
仓库根
├── .claude/             # 共享配置（CLAUDE.md / agents / skills / settings）
├── 杉缔ERP/         # 项目：杉缔ERP
│   ├── PRD文档/         # PRD、业务流程方案、接口文档
│   ├── 原型设计/        # HTML 页面原型
│   ├── 文档/            # 知识库、汇报等非 PRD 业务文档
│   ├── 脚本/            # Python 脚本及依赖
│   └── README.md        # 项目简介与文档导航
├── README.md            # 本索引
```

## 项目目录约定

每个项目内部统一按功能分类归档，新产出物一律放入**对应项目目录**，禁止在仓库根平铺业务文件：

- `{项目}/PRD文档/`：PRD、业务流程方案、接口文档
- `{项目}/原型设计/`：HTML 页面原型
- `{项目}/文档/`：知识库、汇报等非 PRD 业务文档
- `{项目}/脚本/`：Python 脚本及依赖

### 新增项目

1. 在仓库根新建 `{项目名}/` 目录；
2. 项目内创建 `PRD文档/ 原型设计/ 文档/ 脚本/` 四类子目录，并补一份项目 `README.md`；
3. 共享配置（`.claude/CLAUDE.md`、skill、记忆）**零改动**；若该项目规则与基线差异较大，在项目 `README.md` 中补充「专项规则」。

## 版本管理规范

### 提交规范

```
feat: 新增功能/规则
fix: 修复问题/错误
update: 修改已有内容
remove: 删除内容
refactor: 重构/调整结构
docs: 文档格式调整
```

### 版本标签

- `v1.0` - 评审通过版本
- `v1.1` - 迭代版本
