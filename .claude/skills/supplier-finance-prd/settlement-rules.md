# 结算单与对账单业务规则

## 一、单据类型定义

### 1.1 单据分类

| 单据类型 | 适用结算方式 | 业务含义 | 单据状态 |
|---------|-------------|---------|---------|
| **结算单** | 到付、款到发货 | 已完成结算的交易凭证 | 已结算 |
| **对账单** | 周结、半月结、月结 | 待确认+待付款的周期账单 | 待确认→已确认→已付款→已完成 |

### 1.2 核心区别

| 维度 | 结算单 | 对账单 |
|------|-------|-------|
| 生成时机 | 订单完成时即时生成 | 按周期定时生成 |
| 资金状态 | 已结算（钱货两清） | 待结算（存在账期） |
| 供应商操作 | 仅查看确认 | 需确认对账+等待付款 |
| 财务操作 | 记账归档 | 确认异议+安排付款 |
| 是否需要审批 | 否 | 是（异议处理） |

## 二、结算单设计（到付/款到发货）

### 2.1 生成规则

| 结算方式 | 生成时机 | 触发条件 | 单据编号规则 |
|---------|---------|---------|-------------|
| 到付 | 订单签收时 | 物流签收确认 | JS+供应商编码+年月日+流水号 (如: JS-SUP001-20260422-001) |
| 款到发货 | 付款确认时 | 财务确认付款 | 同上 |

### 2.2 结算单字段

| 字段名称 | 数据来源 | 说明 |
|---------|---------|------|
| 结算单号 | 系统生成 | 唯一标识 |
| 关联订单号 | 采购需求单 | 一单一结 |
| 供应商编码 | 采购需求单 | 供应商标识 |
| 供应商名称 | 供应商主数据 | 供应商名称 |
| 结算方式 | 供应商配置 | 到付/款到发货 |
| 商品金额 | 采购需求单 | 实收数量 × 采购单价 |
| 实付金额 | 实际支付 | 实际支付金额 |
| 支付时间 | 支付记录 | 支付/收款时间 |
| 支付渠道 | 支付记录 | 物流代收/银行转账 |
| 结算状态 | 系统维护 | 已结算 |

### 2.4 结算单的业务价值

| 价值点 | 说明 |
|--------|------|
| 交易凭证 | 供应商可下载作为收款凭证 |
| 财务记账 | 财务系统可导入生成记账凭证 |
| 对账依据 | 月底可汇总核对流水 |
| 数据追溯 | 完整的交易记录链路 |

## 三、对账单设计（周结/半月结/月结）

### 3.1 保持原有设计

对账单保持原有设计逻辑：
- 按周期汇总生成
- 需供应商确认
- 支持异议处理
- 需财务安排付款

## 七、数据库设计补充

### 7.1 单据主表设计

```sql
-- 财务单据主表（统一管理结算单和对账单）
CREATE TABLE finance_document (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    document_no VARCHAR(32) NOT NULL COMMENT '单据编号',
    document_type TINYINT NOT NULL COMMENT '单据类型: 1-结算单 2-对账单',
    supplier_id BIGINT NOT NULL COMMENT '供应商ID',
    supplier_code VARCHAR(32) NOT NULL COMMENT '供应商编码',
    supplier_name VARCHAR(100) NOT NULL COMMENT '供应商名称',
    settlement_type VARCHAR(20) NOT NULL COMMENT '结算方式',
    period_start DATE COMMENT '对账周期开始(对账单)',
    period_end DATE COMMENT '对账周期结束(对账单)',
    order_count INT DEFAULT 0 COMMENT '关联订单数',
    product_amount DECIMAL(12,2) DEFAULT 0 COMMENT '商品金额',
    deduct_amount DECIMAL(12,2) DEFAULT 0 COMMENT '扣款金额',
    adjust_amount DECIMAL(12,2) DEFAULT 0 COMMENT '调整金额',
    total_amount DECIMAL(12,2) NOT NULL COMMENT '单据金额',
    paid_amount DECIMAL(12,2) DEFAULT 0 COMMENT '已付金额',
    status TINYINT DEFAULT 10 COMMENT '状态',
    confirm_time DATETIME COMMENT '确认时间',
    confirm_by VARCHAR(50) COMMENT '确认人',
    confirm_type TINYINT COMMENT '确认方式: 1-主动确认 2-自动确认',
    deadline DATETIME COMMENT '确认截止时间',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_supplier (supplier_id),
    INDEX idx_document_type (document_type),
    INDEX idx_status (status),
    INDEX idx_period (period_start, period_end)
);
```

## 八、总结

### 方案优势

| 维度 | 优势说明 |
|------|---------|
| 概念清晰 | 结算单=已结算，对账单=待结算，语义明确 |
| 数据完整 | 所有交易都有单据记录，满足财务合规 |
| 体验友好 | 供应商统一入口查看，区分单据类型 |
| 扩展性好 | 后续可扩展其他单据类型（如退款单） |
| 财务合规 | 支持月度汇总、审计追溯 |

### 实施建议

1. **系统层面**：统一财务管理模块，分tab展示结算单和对账单
2. **流程层面**：到付/款到发货订单完成自动生成结算单，无需人工干预
3. **通知层面**：结算单生成后推送通知供应商，仅作为信息告知
4. **报表层面**：月度汇总报表合并展示，便于财务月结
