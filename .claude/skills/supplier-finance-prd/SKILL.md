## 一、需求背景

为解决供应商对账依赖人工操作、效率低、易出错的问题，实现财务对账流程的数字化、标准化管理，打通从订单完成到结算/对账/付款的全流程数据链路，优化财务与供应商的协同效率，降低跨角色沟通成本，特搭建供应商财务管理系统。

---

## 二、关联系统与数据来源

### 2.1 关联系统

供应商财务管理系统与**订单履约平台**、**易仓ERP**深度联动，实现数据互通、状态同步。

### 2.2 数据来源

- **订单数据**：订单履约平台的已完结采购订单
- **支付数据**：支付系统的支付流水记录
- **供应商数据**：供应商主数据的供应商基础信息、结算配置

---

## 三、核心功能模块

本次供应商财务管理系统的核心功能模块包含：

1. 结算方式配置管理
2. 结算单管理（自动生成、查看、下载/打印）
3. 对账单管理（自动生成、查看、导出）
4. 供应商对账确认（确认、异议提交、异议撤回）
5. 异议处理管理
6. 付款登记管理
7. 月度汇总报表

---

## 四、数据规范

### 4.1 金额精度规则

| 数据项 | 精度要求 | 说明 |
|-------|---------|------|
| 商品金额 | 小数点后4位 | 实收数量 × 采购单价 |
| 扣款金额 | 小数点后4位 | 扣款记录 |
| 调整金额 | 小数点后4位 | 调整记录 |
| 对账金额 | 小数点后4位 | 商品金额 - 扣款金额 + 调整金额 |
| 付款金额 | 小数点后4位 | 本次付款金额 |
| 已付金额 | 小数点后4位 | 累计付款金额 |

## 五、单据体系设计

系统采用"对账单"管理模式：

> **说明**：结算单逻辑本期暂不实现，后续版本再规划。本文档仅保留结算单相关定义供参考，实际开发以对账单功能为主。

### 5.1 单据类型定义

| 单据类型 | 适用结算方式 | 业务含义 | 资金状态 | 单据状态 |
|---------|-------------|---------|---------|---------|
| **结算单**（本期不实现） | 到付、款到发货 | 钱货两清的交易凭证 | 已结算 | 已结算 |
| **对账单** | 周结、半月结、月结 | 存在账期的周期账单 | 待结算 | 待确认→已确认→已付款→已完成 |

### 5.2 单据核心区别

| 维度 | 结算单（本期不实现） | 对账单 |
|------|-------|-------|
| 生成时机 | 订单完成/付款确认时即时生成 | 按周期定时生成 |
| 生成方式 | 单笔订单一单 | 多笔订单汇总 |
| 资金状态 | 已结算（钱货两清） | 待结算（存在账期） |
| 供应商操作 | 仅查看，无需确认 | 需确认/异议 |
| 财务操作 | 记账归档 | 确认异议+安排付款 |
| 状态流转 | 已结算（单一状态） | 待确认→异议中→已确认→已付款→已完成 |

## 六、详细功能设计

### 6.1 结算方式配置管理

在企业内部的供应商管理模块中，为每个供应商配置结算方式及对账规则，系统根据配置自动判断生成结算单或对账单。

#### 6.1.1 新增字段详细配置

| 字段名称 | 字段类型 | 数据源 / 选项 | 默认值 | 规则说明 |
|---------|---------|--------------|-------|---------|
| 结算方式 | 下拉单选 | 到付/款到发货/周结/半月结/月结 | 无（必选） | 固定下拉选项，不可手动输入 |
| 对账日 | 数字输入 | 手动输入1-31 | 无 | 月结时必填，每月几号对账 |
| 账期天数 | 数字输入 | 手动输入正整数 | 无 | 确认后多少天内付款 |
| 开户银行 | 文本输入 | 手动输入 | 无（必填） | 收款银行，最多50字 |
| 银行账号 | 文本输入 | 手动输入 | 无（必填） | 16-19位数字 |
| 联系人 | 文本输入 | 手动输入 | 无（必填） | 对账联系人，最多20字 |
| 联系电话 | 文本输入 | 手动输入 | 无（必填） | 11位手机号 |
| 邮箱 | 文本输入 | 手动输入 | 无（必填） | 接收单据通知，邮箱格式 |

#### 6.1.2 字段联动规则

| 触发条件 | 联动效果 |
|---------|---------|
| 选择"到付"或"款到发货" | 隐藏"对账日"、"账期天数"字段，系统自动生成结算单 |
| 选择"周结" | 隐藏"对账日"字段，账期天数默认7天，系统按周生成对账单 |
| 选择"半月结" | 隐藏"对账日"字段，账期天数默认15天，系统每月1日/16日生成对账单 |
| 选择"月结" | 显示"对账日"字段，默认值1号，系统每月指定日期生成对账单 |

#### 6.1.3 字段必填校验规则

1. **校验时机**：供应商状态为"合作中"，保存结算配置时强制校验
2. **必填字段**：结算方式、开户银行、银行账号、联系人、联系电话、邮箱
3. **条件必填**：
   - 结算方式为"月结"时，"对账日"必填
   - 结算方式为"周结/半月结/月结"时，"账期天数"必填
4. **拦截提示**：任一必填字段为空，前端弹出提示：`请完善结算配置：{字段名}为必填项`

#### 6.1.4 配置修改权限规则

1. **可修改场景**：供应商状态为"合作中"等正常业务环节，支持随时修改结算配置
2. **不可修改场景**：供应商状态变为"已淘汰"，结算配置字段全部锁定，不支持任何修改
3. **修改生效规则**：
   - 结算方式变更后，**下一周期生效**，当前周期不受影响
   - 银行账户变更后，**下次付款生效**
   - 联系人/邮箱变更后，**立即生效**

#### 6.1.5 结算方式变更边界规则

| 变更场景 | 处理规则 |
|---------|---------|
| 结算方式变更时，已存在待确认/异议中/已确认的对账单 | **不做变动**，允许继续走完流程 |
| 结算方式变更时，已存在未完结订单 | 新订单按新结算方式处理 |
| 供应商被淘汰时，存在进行中的对账单 | **不影响**，允许走完流程 |

#### 6.1.6 配置保存后置条件

1. **供应商门户**
   - 更新供应商结算配置缓存
   - 后续订单按新结算方式处理
2. **通知推送**
   - 首次配置：向供应商发送配置完成通知
   - 结算方式变更：向供应商发送变更通知
3. **操作日志**
   - 记录配置变更明细，如"结算方式由'周结'变更为'月结'"

### 6.2 对账单管理

对账单管理实现系统按结算周期自动生成对账单，供应商和财务人员可查看、导出对账单。

#### 6.2.1 对账单自动生成触发方式

1. **周结对账单**
   - 触发时间：每周一 08:00（服务器时间）
   - 数据范围：上周一至周日的已入库订单（按入库时间划分）
   - 编号规则：DZ + 供应商编码 + 年份 + 周号（如：DZ-SUP001-2026-W17）

2. **半月结对账单**
   - 触发时间：每月1日/16日 08:00（服务器时间）
   - 数据范围：上半月（1-15日）/下半月（16日-月末）的已入库订单（按入库时间划分）
   - 编号规则：DZ + 供应商编码 + 年份 + 月份 + H1/H2（如：DZ-SUP001-2026-04-H1）

3. **月结对账单**
   - 触发时间：每月1日 08:00（服务器时间）
   - 数据范围：上月1日至月末的已入库订单（按入库时间划分）
   - 编号规则：DZ + 供应商编码 + 年份 + 月份（如：DZ-SUP001-2026-04）

#### 6.2.2 对账单周期划分规则

| 规则项 | 说明 |
|-------|------|
| 时间依据 | 按**入库时间**划分对账周期 |
| 时间标准 | 使用**服务器时间**，不考虑时区差异 |
| 跨周期归属 | 订单入库时间落入哪个周期，就归属该周期 |

#### 6.2.3 对账单自动生成前置条件

| 序号 | 条件 | 校验方式 | 不满足处理 |
|------|------|---------|-----------|
| 1 | 定时任务触发时间到达 | 定时器触发 | - |
| 2 | 供应商结算方式为"周结/半月结/月结" | 查询供应商配置 | 跳过该供应商 |
| 3 | 供应商状态为"正常" | 查询供应商主数据 | 跳过停用供应商 |
| 4 | 周期内存在已入库订单 | 订单系统查询 | 不生成，记录日志 |
| 5 | 对账金额 > 0 | 计算校验 | **不生成**，记录日志（金额为0不生成对账单） |
| 6 | 订单未在其他对账单中 | 查询去重 | 排除已对账订单 |
| 7 | 该周期未生成过对账单 | 查询去重 | 跳过，避免重复 |

#### 6.2.4 对账单自动生成后置条件

**供应商门户**
- 生成对账单记录，状态为"待确认"
- 计算确认截止时间（生成时间 + 7天）
- 向供应商发送站内信通知
- 向供应商发送邮件通知
- 向供应商联系人发送短信提醒

**订单履约平台**
- 更新订单的对账状态为"已对账"
- 记录生成日志
- 通知财务人员（站内信）

**财务系统**
- 生成应付账款记录

**定时任务**
- 创建超时自动确认定时任务（确认截止时间触发）

#### 6.2.5 对账单字段取值规则

| 字段名称 | 数据来源 | 取值规则 |
|---------|---------|---------|
| 对账单号 | 系统生成 | 按编号规则生成 |
| 供应商编码 | 采购需求单 | 汇总维度 |
| 供应商名称 | 供应商主数据 | 关联查询 |
| 对账周期 | 系统计算 | 根据结算方式确定（如：2026年4月第3周） |
| 确认截止时间 | 系统计算 | 生成时间 + 7天 |
| 订单笔数 | 采购需求单 | COUNT(订单号) |
| 商品金额 | 采购需求单 | SUM(实收数量 × 采购单价) |
| 扣款金额 | 扣款记录表 | SUM(扣款金额) |
| 调整金额 | 调整记录表 | SUM(调整金额) |
| 对账金额 | 计算得出 | 商品金额 - 扣款金额 + 调整金额 |
| 对账状态 | 系统维护 | 待确认 |

#### 6.2.6 对账单列表

为供应商/财务人员展示对账单列表：

1. **展示范围**：
   - 供应商：本供应商所有对账单
   - 财务人员：所有供应商对账单

2. **筛选功能**：支持按**对账周期、对账状态、供应商（仅财务）**筛选

3. **展示字段**：
   - 对账单号、对账周期、供应商名称（仅财务）、订单笔数、商品金额、扣款金额、调整金额、对账金额、确认截止时间、对账状态、操作按钮
   - 确认倒计时（仅待确认状态显示）
   - 超时标签（仅超时状态显示红色标签）

4. **排序功能**：默认按生成时间**倒序**排序

5. **搜索功能**：支持按**对账单号**搜索

6. **功能按钮**：查看详情、导出Excel、确认对账（仅供应商且待确认状态）、提出异议（仅供应商且待确认状态）、登记付款（仅财务且已确认状态）

#### 6.2.7 对账单详情页面

1. **基本信息**：对账单号、供应商名称、对账周期、对账金额、确认截止时间、对账状态

2. **订单明细**：
   - 订单号、商品名称、规格型号、采购单价、实收数量、金额
   - 支持展开查看商品详情

3. **扣款明细**（如有）：
   - 扣款类型、扣款金额、扣款原因、扣款时间

4. **调整明细**（如有）：
   - 调整类型、调整金额、调整原因、调整时间

5. **确认信息**（已确认后显示）：
   - 确认时间、确认人、确认方式（主动确认/自动确认）

6. **付款信息**（已付款后显示）：
   - 付款金额、付款时间、付款方式、付款流水号

7. **操作记录**：所有操作（生成、查看、确认、异议、付款）的操作人、操作时间、操作内容

### 6.3 供应商对账确认

该模块为供应商操作的核心模块，包含对账确认、对账异议提交、异议撤回功能，实现供应商对对账单的线上确认与异议处理。

#### 6.3.1 对账确认

##### 操作场景

仅对账单状态为"待确认"时可操作；"异议中"状态不可操作，异议处理完成后回归待确认可正常操作。

##### 操作流程

1. 供应商点击"确认对账"按钮
2. 系统弹出确认弹窗
   - 显示对账单号、对账周期、对账金额
   - 提示"确认后将进入付款流程，请确认信息无误后再操作"
   - 勾选框"我已核对对账明细，确认无误"
3. 供应商确认
4. 系统记录确认时间、操作人
5. 更新对账单状态为"已确认"
6. 同步至订单履约平台
7. 弹窗提示"确认成功，财务将安排付款"

##### 前置条件

| 序号 | 条件 | 校验方式 | 不满足提示 |
|------|------|---------|-----------|
| 1 | 用户已登录且有"对账确认"权限 | 权限校验 | 请先登录/无权限 |
| 2 | 对账单状态为"待确认" | 状态校验 | 当前状态不允许确认 |
| 3 | 用户为该供应商的授权用户 | 数据权限校验 | 无权操作该对账单 |
| 4 | 对账单未超过确认截止时间 | 时间校验 | 已超过确认截止时间 |
| 5 | 不存在未处理的异议 | 关联数据校验 | 存在未处理的异议，请先处理 |

##### 后置条件

**对账单状态**：变更为"已确认"，不可撤销

**供应商门户**：
- 更新对账单状态
- 取消超时自动确认定时任务
- 向供应商发送确认成功通知

**订单履约平台**：
- 记录确认时间、确认人、确认方式（主动确认）
- 通知财务人员（站内信）

**财务系统**：
- 生成待付款凭证

**供应商额度**：若有授信额度，正式占用

#### 6.3.2 超时自动确认规则

| 项目 | 内容 |
|------|------|
| 触发时间 | 确认截止时间到达 |
| 触发条件 | 对账单状态仍为"待确认" |
| 执行动作 | 自动确认，状态变更为"已确认（自动）" |
| 通知 | 发送通知给供应商和财务 |
| 确认方式标记 | 自动确认 |

#### 6.3.3 对账异议提交

##### 操作场景

仅对账单状态为"待确认"时可操作。

##### 操作流程

1. 供应商点击"提出异议"按钮
2. 系统弹出异议表单
   - 显示对账单号、原对账金额
   - 异议类型（下拉选择）
   - 关联订单（多选，条件必填）
   - 异议金额（必填）
   - 异议说明（文本域，10-500字）
   - 附件上传（可选，最多5个，每个≤5M）
3. 供应商填写并确认提交
4. 系统校验
5. 创建异议记录
6. 更新对账单状态为"异议中"
7. 同步至订单履约平台
8. 弹窗提示"异议已提交，我们将尽快处理"

##### 前置条件

| 序号 | 条件 | 校验方式 | 不满足提示 |
|------|------|---------|-----------|
| 1 | 用户已登录且有"对账异议"权限 | 权限校验 | 请先登录/无权限 |
| 2 | 对账单状态为"待确认" | 状态校验 | 当前状态不允许提交异议 |
| 3 | 用户为该供应商的授权用户 | 数据权限校验 | 无权操作该对账单 |
| 4 | 对账单未超过确认截止时间 | 时间校验 | 已超过确认截止时间，无法提交异议 |
| 5 | 异议说明字数在10-500字之间 | 格式校验 | 异议说明需在10-500字之间 |
| 6 | 附件大小≤5M，数量≤5个 | 文件校验 | 附件超过限制 |

##### 异议类型

| 类型 | 说明 | 必填字段 |
|------|------|---------|
| 订单缺失 | 对账单中缺少应有的订单 | 关联订单（非必填） |
| 金额错误 | 订单金额计算错误 | 关联订单、异议金额 |
| 扣款异议 | 对扣款金额有异议 | 异议金额、异议说明 |
| 其他 | 其他问题 | 异议说明 |

##### 后置条件

**对账单状态**：变更为"异议中"

**供应商门户**：
- 创建异议记录
- 暂停超时自动确认定时任务
- 向供应商发送提交成功通知

**订单履约平台**：
- 通知财务人员（站内信+短信）
- 记录异议提交日志

**付款流程**：暂停付款流程，等待异议处理完成

#### 6.3.4 异议撤回

##### 操作场景

仅异议状态为"待处理"时可操作。

##### 操作流程

1. 供应商点击"撤回异议"按钮
2. 系统弹出确认弹窗
3. 供应商确认
4. 更新异议状态为"已撤回"
5. 对账单状态恢复为"待确认"
6. 弹窗提示"异议已撤回"

##### 前置条件

| 序号 | 条件 | 校验方式 | 不满足提示 |
|------|------|---------|-----------|
| 1 | 用户已登录且有"异议撤回"权限 | 权限校验 | 请先登录/无权限 |
| 2 | 异议状态为"待处理" | 状态校验 | 当前状态不允许撤回 |
| 3 | 用户为该异议的提交人或同供应商管理员 | 数据权限校验 | 无权撤回该异议 |
| 4 | 异议提交时间在24小时内 | 时间校验 | 超过24小时无法撤回 |

##### 后置条件

**异议状态**：变更为"已撤回"

**对账单状态**：恢复为"待确认"

**定时任务**：恢复超时自动确认任务

**通知**：通知财务人员（异议已撤回）

### 6.4 异议处理管理

异议处理管理为企业内部核心操作模块，财务人员处理供应商提交的对账异议，可选择同意调整或驳回。

#### 6.4.1 异议列表

1. **展示范围**：所有供应商提交的异议记录

2. **筛选功能**：支持按**异议状态、供应商、异议类型、提交时间**筛选

3. **展示字段**：
   - 异议单号、对账单号、供应商名称、异议类型、异议金额、原对账金额、差异金额、提交时间、异议状态、操作按钮

4. **排序功能**：默认按提交时间**倒序**排序

5. **功能按钮**：查看详情、处理（仅待处理状态）

#### 6.4.2 异议详情页面

1. **异议信息**：
   - 异议单号、对账单号、供应商名称、异议类型、提交时间、异议状态

2. **异议详情**：
   - 原对账金额、异议金额、差异金额
   - 异议说明
   - 关联订单（如有）
   - 附件（如有）

3. **订单核实**（如有关联订单）：
   - 订单号、商品名称、采购数量、采购单价、采购金额
   - 实收数量、入库时间
   - 差异数量、差异金额（若有差异则高亮显示）

4. **处理意见**：
   - 同意调整：调整后金额输入框
   - 驳回异议：驳回原因输入框

5. **操作按钮**：取消、提交处理

#### 6.4.3 异议处理流程

##### 同意调整

1. 财务选择"同意调整"
2. 输入调整后金额（默认值为异议金额，可修改）
3. 系统实时显示调整差额
4. 点击"提交处理"
5. 系统弹出确认弹窗
6. 确认后执行：
   - 更新异议状态为"已通过"
   - 更新对账单金额
   - 对账单状态变更为"待确认"
   - 重新计算确认截止时间（处理时间 + 7天）
   - 通知供应商重新确认

##### 驳回异议

1. 财务选择"驳回异议"
2. 输入驳回原因（必填）
3. 点击"提交处理"
4. 系统弹出确认弹窗
5. 确认后执行：
   - 更新异议状态为"已驳回"
   - 对账单状态变更为"待确认"
   - 通知供应商驳回结果

##### 前置条件

| 序号 | 条件 | 校验方式 | 不满足提示 |
|------|------|---------|-----------|
| 1 | 用户已登录且有"异议处理"权限 | 权限校验 | 请先登录/无权限 |
| 2 | 异议状态为"待处理" | 状态校验 | 当前状态不允许处理 |
| 3 | 用户有该供应商的处理权限 | 数据权限校验 | 无权处理该供应商异议 |
| 4 | 同意调整时：调整后金额必须>0 | 数据校验 | 调整后金额必须大于0 |
| 5 | 驳回时：驳回原因必填 | 数据校验 | 请填写驳回原因 |

##### 后置条件

**同意调整后**：

| 影响范围 | 影响内容 |
|---------|---------|
| 异议状态 | 已通过 |
| 对账单金额 | 更新为调整后金额 |
| 对账单状态 | 待确认，需供应商重新确认 |
| 确认截止时间 | 重新计算（处理时间+7天） |
| 供应商额度 | 按调整后金额占用 |

**驳回异议后**：

| 影响范围 | 影响内容 |
|---------|---------|
| 异议状态 | 已驳回 |
| 对账单金额 | 保持原金额 |
| 对账单状态 | 待确认，供应商可再次异议或确认 |
| 确认截止时间 | 保持原截止时间 |

#### 6.4.4 供应商后续操作

- **同意调整后**：供应商可确认调整后金额或再次提交异议
- **驳回异议后**：供应商可确认原金额或再次提交异议
- **无限制**：供应商申请被驳回后，重新发起异议无时间间隔与次数限制

### 6.5 付款登记管理

付款登记管理为企业内部核心操作模块，财务人员登记对账单的付款信息，支持分批付款。

> **说明**：付款功能仅为对账单状态变更和填写付款金额，**不需要审批流程**。

#### 6.5.1 付款登记前置条件

| 序号 | 条件 | 校验方式 | 不满足提示 |
|------|------|---------|-----------|
| 1 | 用户已登录且有"付款登记"权限 | 权限校验 | 请先登录/无权限 |
| 2 | 对账单状态为"已确认" | 状态校验 | 当前状态不允许付款登记 |
| 3 | 用户有该供应商的处理权限 | 数据权限校验 | 无权处理该供应商付款 |
| 4 | 本次付款金额≤待付金额 | 数据校验 | 付款金额不能超过待付金额 |
| 5 | 本次付款金额>0 | 数据校验 | 付款金额必须大于0 |
| 6 | 付款日期≤今天 | 日期校验 | 付款日期不能超过今天 |
| 7 | 付款流水号不为空 | 数据校验 | 请输入付款流水号 |

#### 6.5.2 付款登记字段

| 元素名称 | 类型 | 必填 | 校验规则 | 说明 |
|---------|------|-----|---------|------|
| 对账单号 | 只读 | - | - | 显示对账单号 |
| 供应商名称 | 只读 | - | - | 显示供应商名称 |
| 对账金额 | 只读 | - | - | 显示对账金额 |
| 已付金额 | 只读 | - | - | 显示已付款金额 |
| 待付金额 | 只读 | - | - | 对账金额 - 已付金额 |
| 本次付款金额 | 金额输入 | 是 | ≤待付金额且>0 | 本次付款金额 |
| 付款日期 | 日期选择 | 是 | ≤今天 | 实际付款日期 |
| 付款方式 | 下拉选择 | 是 | 必选 | 银行转账/支票/承兑汇票 |
| 付款流水号 | 文本输入 | 是 | 最多50字 | 银行流水号 |
| 付款凭证 | 文件上传 | 否 | 图片/PDF | 付款凭证截图 |
| 备注 | 文本域 | 否 | 最多200字 | 付款备注 |

#### 6.5.3 付款登记流程

1. 财务选择已确认的对账单
2. 点击"付款登记"按钮
3. 系统弹出付款表单
   - 显示对账单号、供应商名称、对账金额、已付金额、待付金额
4. 财务填写付款信息
   - 系统实时计算付款进度
5. 点击"确认付款"
6. 系统弹出确认弹窗
7. 确认后执行付款登记

#### 6.5.4 付款登记后置条件

**部分付款**（本次付款金额 < 待付金额）：

| 影响范围 | 影响内容 |
|---------|---------|
| 对账单状态 | 已付款 |
| 已付金额 | 累加本次付款金额 |
| 供应商门户 | 显示部分付款信息 |
| 供应商额度 | 部分释放 |
| 财务系统 | 生成付款凭证 |

**全额付款**（本次付款金额 = 待付金额）：

| 影响范围 | 影响内容 |
|---------|---------|
| 对账单状态 | 已完成 |
| 已付金额 | 等于对账金额 |
| 供应商门户 | 显示已完成 |
| 供应商额度 | 全部释放 |
| 财务系统 | 生成结清凭证 |

**通知**：
- 向供应商发送站内信+短信通知
- 同步到财务系统

#### 6.5.5 分批付款场景

```
对账金额: ¥100,000

第一次付款:
    本次付款: ¥50,000
    │
    ├─→ 状态变为"已付款"
    │
    └─→ 付款进度: 50%

第二次付款:
    本次付款: ¥30,000
    │
    ├─→ 状态仍为"已付款"
    │
    └─→ 付款进度: 80%

第三次付款:
    本次付款: ¥20,000
    │
    ├─→ 状态变为"已完成"
    │
    └─→ 付款进度: 100%
```

## 七、状态机设计

### 7.1 结算单状态

```
┌──────────┐  订单完成/付款确认   ┌──────────┐
│   初始   │ ─────────────────→ │  已结算  │
└──────────┘                     └──────────┘
```

| 状态 | 状态码 | 触发条件 | 可执行操作 | 说明 |
|------|-------|---------|----------|------|
| 已结算 | 100 | 结算单生成 | 查看、下载、打印 | 最终状态 |

### 7.2 对账单状态流转

```
┌──────────┐  自动生成   ┌──────────┐  确认对账   ┌──────────┐
│   初始   │ ─────────→ │  待确认  │ ─────────→ │  已确认  │
└──────────┘            └────┬─────┘            └────┬─────┘
                             │                       │
                             │ 提出异议               │ 登记付款
                             ↓                       ↓
                        ┌──────────┐            ┌──────────┐
                        │  异议中  │            │  已付款  │
                        └────┬─────┘            └────┬─────┘
                             │                       │
                             │ 处理完成               │ 全额付款
                             │                       │
                             └───────────┬───────────┘
                                         ↓
                                   ┌──────────┐
                                   │  已完成  │
                                   └──────────┘
```

| 状态 | 状态码 | 触发条件 | 可执行操作 | 说明 |
|------|-------|---------|----------|------|
| 待确认 | 10 | 对账单生成 | 查看、确认、异议 | 初始状态 |
| 异议中 | 20 | 供应商提交异议 | 查看、处理异议 | 暂停付款流程 |
| 已确认 | 30 | 供应商确认/自动确认 | 查看、登记付款 | 可进入付款 |
| 已付款 | 40 | 部分付款 | 查看、继续付款 | 等待剩余付款 |
| 已完成 | 50 | 全额付款 | 查看 | 最终状态 |

### 7.3 异议状态流转

┌──────────┐  提交异议   ┌──────────┐  处理完成   ┌──────────┐

                        └──────────┘

## 九、权限控制要求

1. **结算配置权限**：仅财务主管、财务专员可配置供应商结算方式
2. **供应商门户数据隔离**：供应商仅能查看本供应商的结算单/对账单，无法查看其他供应商数据
3. **异议处理权限**：仅财务主管、财务专员可处理异议
4. **付款登记权限**：仅财务主管、财务专员可登记付款
5. **报表导出权限**：财务人员可导出所有供应商报表，供应商仅可导出本供应商报表

---

## 十、数据同步要求

1. **实时性**：供应商门户与订单履约平台的单据状态、操作信息需**实时同步**，确保双方信息一致
2. **准确性**：结算单、对账单的金额、订单明细等核心数据，在跨系统同步时需做校验，避免数据偏差
3. **异常处理**：若数据同步失败（如对账单同步门户失败、付款信息同步财务系统失败），需标记对应异常状态，并支持人工重试同步
4. **重试机制**：同步失败后间隔5分钟重试，最多3次，失败后发送告警通知
