# B 端产品多项目文档库 - 顶层配置

> 本仓库是**多项目文档库容器**：`.claude/CLAUDE.md`、`agents/`、`skills/`、记忆对各项目**共享**，业务文档**按项目分目录**存放。
> 下方「杉缔ERP」基线规则为全仓默认，各项目若无专项差异即继承沿用（规则相近可共用）；存在差异时在对应项目内补充专项规则。

## 0. 仓库结构

```
仓库根
├── .claude/               # 共享配置层：CLAUDE.md、agents、skills、settings（勿放业务文档）
├── 杉缔ERP/           # 项目 A：订单履约 / 供应商门户 / 财务对账 / 易仓采购 / 拆单Agent
│   ├── README.md          # 项目简介 + 文档导航（含专项规则，若有）
│   ├── PRD文档/  ├── 原型设计/  ├── 文档/  └── 脚本/
├── {未来项目}/             # 新增项目 = 新建同名目录 + 内建四类功能子目录
└── README.md              # 多项目索引
```

### 新增项目步骤（共享配置零改动）
1. 在仓库根新建 `{项目名}/` 目录；
2. 项目内创建 `PRD文档/ 原型设计/ 文档/ 脚本/` 四个子目录，并补一份项目 `README.md`；
3. 若该项目规则与 ERP 基线差异较大：在项目 `README.md` 中写明「专项规则」，产出该项目的文档时专项规则优先于基线。

## 1. 产品基础信息（杉缔ERP · 默认基线）
- **产品名称**：杉缔ERP
- **核心业务**：多平台订单管理、采购、仓储、物流、财务、报价核算
- **主要用户**：跨境卖家、运营、采购员、仓库管理员、财务
- **用户角色**：B端产品经理，熟悉B端产品方法论，输出符合PRD规范的结构化内容

## 2. 业务约束与规则

### 权限控制
- 模型：基于角色的访问控制（RBAC）
- **所有数据导出功能必须经过权限校验**，不允许绕过。导出接口需记录操作日志（谁、何时、导出了什么范围的数据）。
- **所有新增按钮必须配置权限控制**，无权限时按钮置灰或隐藏。按钮表必须有"权限控制"列。

### 数据安全
- 敏感字段（如手机号、地址、成本价）默认必须脱敏处理。
- 如业务方明确要求不脱敏，需在PRD中单独标注并说明原因。
- 导出行数限制：默认单次导出最大10000行，如业务方另有要求需在PRD中说明。

### 业务逻辑禁区
- 报价计算、折扣叠加、运费模板等核心公式不可随意修改，如需改动必须经过评审。
- 删除客户/订单数据需二次确认，且记录删除原因。
- 涉及多平台（Amazon、Shopify等）的库存同步逻辑不得直接写死平台 ID。

## 4. PRD输出规范

### 规则优先级
**生成文档时，强制约束的取用顺序：**
1. **本次需求中用户明确指定的规则**（最高优先级，覆盖下方所有默认规则）
2. **项目专项规则**（若该项目 README 已声明；仅作用于该项目）
3. **本文件（CLAUDE.md）中的业务约束与规则**（全局默认基线）
4. **prd-writer agent中的结构化要求**（模板级）

### PRD输出结构
输出PRD前**必须先确认需求类型**，再决定文档结构：

**迭代需求**（已有功能做调整）：
- 精简输出，不输出：项目背景、商业分析、同类调研、项目收益、完整架构图、ER全景图、术语表、参考文献
- 只输出：变更背景（一句话）、功能变更清单、业务规则、页面交互变更、异常处理、待确认事项
- 简单修改/逻辑调整：不画状态机和流程图，直接用规则表说清
- 新功能（即使是迭代中的新功能）：保留流程图、状态机等设计图

**0-1新需求**（全新系统/模块构建）：
- 完整PRD结构输出

### PRD文件存放
- 各项目 PRD 统一存放到 `{项目名}/PRD文档/` 目录下，禁止在项目目录外新建文档目录
- 文件命名：`{项目名}/PRD文档/{需求名称}PRD.md`，禁止在文件名中出现空格
- 当前存量项目：杉缔ERP 文档统一存放于 `杉缔ERP/PRD文档/`

### 项目目录规划
- 每个项目内部统一按功能子目录组织：
  - `PRD文档/`：PRD 文档、业务流程方案、接口文档
  - `原型设计/`：HTML 页面原型
  - `文档/`：知识库、汇报等非 PRD 业务文档
  - `脚本/`：Python 脚本及依赖
- 仓库根目录仅允许出现：各项目目录、`.claude/`、`README.md`、`.gitignore` 等配置文件
- 禁止在仓库根平铺业务文件；新产出物一律放入对应项目目录
- skill 目录只放指令与参考规则，不放业务文档

## 5. 协作规则
- **信息不足时主动反问**：如果上下文信息不足以完成任务，必须先向用户提问确认，禁止自行编造内容。
