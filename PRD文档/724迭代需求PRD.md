# 724迭代需求 PRD文档

---

## 一、变更背景

本次迭代主要解决四个业务痛点：
1. 导出字段不够完善，运营需要商品图片、内部SKU等信息用于线下对账和分析
2. 采购订单缺少跟单员/采购员维度，无法按人员筛选和统计
3. 外部商品不支持关联多个供应商，无法灵活应对供应链变化
4. 仓发邀约依赖人工操作，需要系统自动化识别并生成需求单

---

## 三、功能详细设计

### 3.1 导出优化

#### 3.1.1 Shopify订单导出 - 增加商品图片链接

**变更说明**：导出字段新增"商品图片链接"列

| 字段 | 说明 |
|------|------|
| 商品图片链接 | 商品主图的内部存储地址，支持直接浏览器访问 |

**导出范围**：订单履约平台（shopify订单列表）的导出功能

#### 3.1.2 待同步商品列表导出 - 增加内部SKU

**变更说明**：导出字段新增"内部SKU"列

| 字段 | 说明 |
|------|------|
| 内部SKU | 商品内部SKU编码，查询商品运营平台 |

**导出范围**：订单履约模块的待同步商品列表导出

#### 3.1.3 采购单导出 - 增加已发货/未发货数量

**变更说明**：导出字段新增两个数量统计字段

| 字段 | 说明 |
|------|------|
| 已发货数量 | 该采购单行项目中已发货的数量累计 |
| 未发货数量 | 该采购单行项目中未发货的数量（采购数量 - 已发货数量） |

**业务规则**：
- 统计维度：按采购单行项目级统计
- 已发货数量 = 该行项目关联的所有发货单中已确认发货的数量之和
- 未发货数量 = 采购数量 - 已发货数量
- 若未发货数量 = 0，表示该行项目已全部发货

#### 3.2.1 背景说明

拆单管理模块现有筛选功能不支持批量查询，运营在处理大量订单时效率较低。本次迭代新增Shopify订单号和子订单号的批量查询功能，并支持子订单号模糊查询。

| 变更项 | 原逻辑 | 新逻辑 |
|--------|--------|--------|
| 查询方式 | 单个查询 | 支持批量查询（逗号分隔） |
| 匹配方式 | 精确匹配 | 精确匹配 |

**子订单号筛选**：

| 变更项 | 原逻辑 | 新逻辑 |
|--------|--------|--------|
| 查询方式 | 单个查询 | 支持批量查询（逗号分隔） |
| 匹配方式 | 精确匹配 | 支持模糊查询（LIKE） |

#### 3.2.3 业务规则

| 规则 | 说明 |
|------|------|
| 批量查询分隔符 | 逗号（,）分隔多个订单号 |
| 子订单号模糊查询 | 支持前后模糊匹配（%keyword%） |
| 查询优先级 | 精确匹配优先于模糊匹配 |

### 3.4 待同步商品列表支持多供应商

#### 3.4.1 背景说明

现有系统外部商品仅支持关联单一供应商，无法灵活应对供应链变化（如供应商缺货、价格调整等）。本次迭代支持外部商品关联多个供应商，并设置默认供应商。修改默认供应商后自动同步至商品运营平台（POP），确保两端数据一致。

#### 3.4.2 业务规则

| 规则 | 说明 |
|------|------|
| 设置入口 | 外部商品详情页 |
| 数据录入 | 手动录入供应商关联关系 |
| 默认供应商 | 手动设置，支持切换 |
| 供应商数量 | 无限制 |
| 供应商停用 | 不做特殊处理，保留关联关系 |

#### 3.4.3 历史数据处理

| 处理项 | 说明 |
|--------|------|
| 处理范围 | 待同步商品列表中所有历史数据 |
| 处理规则 | 历史数据的商品与供应商为一对一关系，自动将该供应商设置为默认供应商 |
| 执行时机 | 系统上线时自动执行数据迁移 |
| 数据示例 | 商品A-供应商B（历史）→ 商品A-供应商B（默认供应商=是） |

#### 3.4.4 页面交互变更

**外部商品详情页**：

- 新增"供应商管理"卡片区域
- 展示已关联的供应商列表
- 支持添加供应商（下拉选择）
- 支持删除供应商关联
- 支持设置默认供应商（单选按钮）
- 默认供应商标识：✅ 标记

#### 3.4.5 POP平台同步

待同步商品列表修改默认供应商保存后，自动同步至商品运营平台（POP）。

**同步场景**：

| 场景 | 触发时机 | 说明 |
|------|----------|------|
| 待同步商品列表 | 更新默认供应商保存后立即同步 | 订单履约平台 > 供应商管理 > 待同步商品列表 |

**同步内容**：

| 字段 | 说明 |
|------|------|
| 默认供应商 | 更新后的默认供应商ID |

**同步逻辑**：

```plaintext
1. 用户在待同步商品列表更新默认供应商并保存
2. 系统立即调用POP平台接口同步默认供应商
3. 接口返回结果处理：
   a. 同步成功 → 更新本地状态为"已同步"
   b. 同步失败 → 保持"待同步"状态，记录失败原因，支持重试
```

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| POP接口调用失败 | 保持"待同步"状态，记录失败日志，支持手动重试 |
| 网络超时 | 异步重试3次，仍失败则记录异常 |

#### 3.4.6 下游影响

创建采购需求时，供应商字段的取值逻辑：
- 若外部商品默认选中默认供应商

### 3.5 需求管理完成下单自动校验供应商产品是否存在

#### 3.5.1 背景说明

需求管理完成下单时，需自动校验易仓是否存在供应商产品关联，若不存在则自动创建，确保下单流程顺畅。

#### 3.5.2 调用时机

| 场景 | 触发时机 | 说明 |
|------|----------|------|
| 生产需求 | 点击完成下单时 | 下单前先检查并同步 |
| 需求管理 | 点击完成下单时（触发自动下单） | 下单前先检查并同步 |

#### 3.5.3 调用逻辑

```plaintext
1. 用户点击完成下单
2. 调用易仓接口【查询供应商产品列表】getSupplierProductList
   - 请求参数：sku=需求单内所有SKU（支持批量），supplier_code=供应商编码
3. 根据返回结果判断：
   a. 所有SKU均已存在供应商产品 → 跳过创建，直接完成下单
   b. 部分SKU不存在供应商产品 → 对不存在的SKU调用【建立供应商产品关联】syncSupplierProduct
      - 全部创建成功 → 继续完成下单
      - 任一创建失败 → 阻断下单，提示用户失败原因
```

#### 3.5.4 接口规范

**接口一：查询供应商产品列表**getSupplierProductList

| 参数 | 说明 | 取值 |
|------|------|------|
| sku | SKU编码（支持批量） | 需求单内所有SKU 空格分隔 |
| supplier_code | 供应商编码 | 需求单关联的供应商编码 |

**接口二：建立供应商产品关联**syncSupplierProduct

| 参数 | 说明 | 取值 |
|------|------|------|
| action_type | 操作类型 | ADD（新增） |
| supplier_id | 供应商ID | 需求单关联的供应商ID |
| sp_supplier_product_code | 供应商产品代码 | 商品内部SKU |
| sp_min_qty | 最小起订量 | 默认1 |
| buyer_id | 采购员 | 取供应商绑定的采购员 |

#### 3.5.5 异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| 查询接口调用失败 | 阻断下单，提示用户"查询供应商产品失败：{具体原因}" |
| 创建接口调用失败 | 阻断下单，提示用户"供应商产品关联创建失败：{具体原因}" |
| 供应商未绑定采购员 | 阻断下单，提示用户"供应商未绑定采购员，请先完善供应商信息" |

### 3.6 仓发邀约线上化

#### 3.6.1 功能概述

建立自动化的仓库邀约机制，通过外部Agent调用订单履约平台提供的接口实现邀约规则判断和需求单创建。

**实现方式**：
- 订单履约平台提供两个标准API接口
- 外部Agent负责邀约规则判断，调用接口获取数据并创建需求单
- 订单履约平台负责数据提供和需求单管理

#### 3.6.2 接口规范

**接口一：查询订单商品数据**

```
GET /v1/products/fulfillment-data
```

**请求参数**：

| 参数 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| sales_start | string | 是 | 近7天起始日期 | `2026-07-03` |
| sales_end | string | 是 | 近7天结束日期 | `2026-07-09` |

**返回结构**：

```json
{
  "data": [
    {
      "product_id": "xxx",
      "product_name": "夏季连衣裙",
      "warehouse_id": "WH-CN-SH",
      "supplier_code": "SUP001",
      "is_first_invitation": true,
      "skus": [
        {
          "sku": "LZ-S",
          "sales_7d": 6,
          "sales_cumulative": 200,
          "stock_in_warehouse": 3,
          "stock_in_transit": 5
        }
      ]
    }
  ]
}
```

**返回字段说明**：

| 层级 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 商品级 | product_id | string | 商品SPU |
| | product_name | string | 商品名称 |
| | warehouse_id | string | 仓库ID |
| | supplier_code | string | 供应商编码（默认供应商） |
| | is_first_invitation | bool | 是否首次邀约（未创建过仓发邀约需求单） |
| SKU级 | sku | string | SKU编码 |
| | sales_7d | int | 近7天销量 |
| | sales_cumulative | int | 历史累计销量 |
| | stock_in_warehouse | int | 在仓可用库存 |
| | stock_in_transit | int | 在途数量 |

**平台内部查询规则**：

**Step 1：筛选近7天有动销的SKU**

| # | 规则项 | 具体条件 |
|---|--------|---------|
| 1 | 时间范围 | `下单时间 BETWEEN '{sales_start}' AND '{sales_end}'`（含头含尾，7天） |
| 2 | 订单状态 | `status != '待支付'` 排除待支付订单 |
| 3 | 仓发地 | `仓发地 = '国内'` |
| 4 | 商品类型 | `商品类型 NOT IN ('AIGC', 'POD')` |
| 5 | 订单标签 | `tags` 不包含 `'网红寄样'` |
| 6 | 去重聚合 | `GROUP BY sku HAVING SUM(quantity) > 0` |

**Step 2：基于Step1的SKU列表，查询各项数据**

| 数据项 | 数据源 | 口径 |
|--------|--------|------|
| sales_7d | 动销订单表 | 近7天销量，过滤条件同Step1 |
| sales_cumulative | 动销订单表 | 历史累计销量，不限时间范围 |
| stock_in_warehouse | 库存系统/WMS | 可用库存（可发货，不含锁定/残次/冻结） |
| stock_in_transit | 需求单明细表 | 需求单明细行状态排除：待确认、已完结、已终止，其余状态=在途 |
| is_first_invitation | 需求单表 | 该商品SPU是否创建过仓发邀约需求单：从未创建过→true（首次邀约），已有需求单记录→false（补仓） |
| supplier_code | 供应商表 | 默认供应商编码，通过外部商品关联的默认供应商获取 |
| 商品基本信息 | 商品主数据表+供应商表 | 通过SKU反查所属商品，供应商过滤：状态='合作中'、启用=true、标签包含'仓发邀约' |

**整体查询流程图**：

```
请求参数: sales_start, sales_end
         │
         ▼
┌─────────────────────────────────────────┐
│  Step 1: 动销订单表                       │
│  条件: 时间窗口 + 状态 + 仓发地 + 商品类型  │
│       + 排除网红寄样                       │
│  结果: 符合条件的 SKU 列表                 │
└──────────┬──────────────────────────────┘
           │
    ┌──────┼──────┬──────────┬──────────┬──────────┐
    ▼      ▼      ▼          ▼          ▼          ▼
  sales_ sales_  stock_    stock_    is_first  supplier 商品
  7d     cumul   warehouse transit  invitation  code   主数据
 (同表)  (同表)  (库存表)  (采购表) (需求单表) (供应商表)(商品表)
    │      │      │          │          │        │       │
    └──────┴──────┴──────────┴──────────┴────────┴───────┘
                              │
                              ▼
                      组装 JSON 返回
```

**接口二：创建需求单**

```
POST /v1/demand-orders
```

**请求参数**：

```json
{
  "items": [
    {
      "sku": "LZ-S",
      "quantity": 3,
      "warehouse_id": "WH-CN-SH",
      "is_first_invitation": true
    }
  ]
}
```

**请求参数说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| items | array | 是 | SKU明细列表 |
| items[].sku | string | 是 | SKU编码 |
| items[].quantity | int | 是 | 采购数量 |
| items[].warehouse_id | string | 是 | 仓库ID |
| items[].is_first_invitation | bool | 是 | 是否首次邀约（true=首次邀约，false=补仓） |

**返回结构**：

```json
{
  "demand_order_id": "DM-20260710020000",
  "items_created": 4
}
```

**返回字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| demand_order_id | string | 需求单号 |
| items_created | int | 创建的SKU数量 |

#### 3.6.3 Agent调用流程

```plaintext
1. Agent定时触发（凌晨2:00，可配置）
2. 调用接口一查询订单商品数据
   - 获取商品SPU、SKU、销量、库存等数据
   - 获取supplier_code字段（供应商编码）
   - 获取is_first_invitation字段（标识是否首次邀约）
3. Agent根据业务规则判断：
   a. 首次邀约条件判断
   b. 补仓条件判断
4. Agent调用接口二创建需求单
   - 传入SKU、数量、仓库ID
   - 传入is_first_invitation字段（从接口一获取）
5. 订单履约平台生成需求单（状态：待确认）
   - 根据is_first_invitation字段设置标签（详见3.6.6标签规则）
6. 运营在订单履约平台确认需求单
7. 确认后自动生成采购单，继承需求单标签
8. 采购单生成采购订单，继承采购单标签
```

#### 3.6.4 需求单字段

复用现有采购需求单表，新增以下字段：

| 字段 | 说明 |
|------|------|
| 需求类型 | 仓发邀约 |
| 首次/补仓标识 | 首次邀约 或 补仓 |


#### 3.6.5 首次与补仓标识规则

**标签逻辑**：

| 场景 | 标签规则 | 说明 |
|------|----------|------|
| 所有通过Agent创建的需求单（给个参数，通过参数区分） | 统一打上"仓发邀约"标签 | 基础标签 |
| 首次邀约（is_first_invitation=true） | 额外打上"首次邀约"标签 | 双标签：仓发邀约 + 首次邀约 |
| 补仓（is_first_invitation=false） | 仅"仓发邀约"标签 | 单标签：仓发邀约 |

**标签继承规则**：

### 3.7 在途数量定义变更

#### 3.7.1 背景说明

原缺货数量计算方案中，在途数量的定义包含待确认状态的需求单。本次迭代要求在途的定义排除待确认的需求单，避免重复计算。

#### 3.7.2 变更说明

**原定义**：

| 数据项 | 定义 |
|--------|------|
| 在途数量 | 履约平台中所有需求SKU状态为待确认+待下单+待接单+已接单+进行中的SKU数量 |

**新定义**：

| 数据项 | 定义 |
|--------|------|
| 在途数量 | 履约平台中所有需求SKU状态为待下单+待接单+已接单+进行中的SKU数量（排除待确认） |

#### 3.7.3 变更影响

| 影响范围 | 说明 |
|----------|------|
| 缺货计算 | 缺货数量 = 需求数量 - 可用库存 - 在途数量 |
| 需求生成 | 在途数量减少，可能导致更多SKU触发需求生成 |
| 接口返回 | 接口一返回的stock_in_transit字段口径同步变更 |

#### 3.7.4 接口变更

**接口一返回字段说明更新**：

| 字段 | 原口径 | 新口径 |
|------|--------|--------|
| stock_in_transit | 需求单明细行状态排除：已完结、已终止，其余状态=在途 | 需求单明细行状态排除：待确认、已完结、已终止，其余状态=在途 |

### 3.8 仓发邀约仓库配置

#### 3.8.1 背景说明

自动创建仓发邀约需求单时，需要指定仓库。本次迭代在现有仓库管理页面上新增"仓发邀约仓库"开关，支持手动单独设置。

#### 3.8.2 配置入口

**路径**：订单履约平台 > 基础数据 > 仓储设置 > 仓库管理

**配置变更**：

| 配置项 | 类型 | 说明 |
|--------|------|------|
| 默认采购仓库 | 开关 | 现有功能，设置默认采购仓库 |
| 仓发邀约仓库 | 开关 | 新增，设置仓发邀约的默认仓库 |

#### 3.8.3 业务规则

| 规则 | 说明 |
|------|------|
| 选择范围 | 系统中所有已启用的仓库 |
| 选择数量 | 只允许选择一个仓库作为仓发邀约仓库 |
| 必填性 | 配置后生效，未配置时自动创建需求单会提示配置 |
| 修改规则 | 支持修改，修改后新的需求单使用新仓库，已创建的需求单不受影响 |
| 与默认采购仓库关系 | 两者独立设置，可相同也可不同 |

#### 3.8.4 自动创建需求单逻辑

```plaintext
1. Agent触发自动创建需求单
2. 系统读取"仓发邀约仓库"配置
3. 若已配置：
   a. 需求单的仓库字段默认选中该仓库
4. 若未配置：
   a. 提示"请先配置仓发邀约仓库"
   b. 阻断需求单创建
```

#### 3.8.5 页面交互

**仓库管理页面**：

- 在现有"默认采购仓库"开关下方新增"仓发邀约仓库"开关
- 开关形式，开启表示设置为仓发邀约仓库
- 同一时间只能开启一个仓库的"仓发邀约仓库"开关

**配置校验**：

- 开启时校验仓库是否有效（已启用、未删除）
- 仓库被停用时自动关闭开关

### 3.10 入库通知同步易仓参数传递

#### 3.10.1 背景说明

入库通知关联采购单时，若采购单带有"仓发邀约"标签，需要在同步易仓时将该标签信息传递给易仓系统，便于易仓端进行标识和处理。

#### 3.10.2 业务规则

| 规则 | 说明 |
|------|------|
| 触发条件 | 入库通知关联的采购单带有"仓发邀约"标签 |
| 传递字段 | 入库通知产品明细对象的note字段 |
| 传递内容 | "仓发邀约" |
| 适用范围 | 该入库通知下的所有产品明细 |

#### 3.10.3 调用逻辑

```plaintext
1. 入库通知关联采购单
2. 检查采购单是否带有"仓发邀约"标签
3. 若有标签：
   a. 同步易仓时，设置Request.product_list.note='仓发邀约'
   b. 该入库通知下的所有产品明细均携带此备注
4. 若无标签：
   a. note字段为空或不传递
```

#### 3.10.4 接口参数变更

**易仓同步接口新增参数**：

| 参数 | 类型 | 说明 | 取值逻辑 |
|------|------|------|----------|
| product_list.note | string | 产品备注 | 若采购单有"仓发邀约"标签，则为"仓发邀约"；否则为空 |

#### 3.10.5 示例

**场景一：采购单有仓发邀约标签**

```
采购单：PO-20260708-001（标签：仓发邀约）
入库通知：IN-20260708-001
产品明细：
  - SKU-A，note='仓发邀约'
  - SKU-B，note='仓发邀约'
  - SKU-C，note='仓发邀约'
```

**场景二：采购单无仓发邀约标签**

```
采购单：PO-20260708-002（无标签）
入库通知：IN-20260708-002
产品明细：
  - SKU-A，note=''
  - SKU-B，note=''
  - SKU-C，note=''
```

## 四、异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| Agent调用接口一失败 | Agent记录失败日志，支持重试 |
