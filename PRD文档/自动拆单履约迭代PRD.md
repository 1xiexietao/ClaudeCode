# 自动拆单履约迭代 PRD文档

## 一、功能概述

**菜单名称**：拆单管理

**所属系统**：订单履约平台

**功能说明**：展示Shopify订单拆单后的结果集，支持拆单后的履约操作，包括手动拆单、修改仓发地、标记发货、同步易仓等。

---

## 二、页面结构

### 2.1 整体布局

*   **顶部导航栏**：Logo、页面标题、版本号、用户头像
    
*   **筛选区域**：多条件组合筛选
    
*   **数据列表**：两级表格结构（订单级 + 子订单级）
    
*   **分页组件**：底部分页导航
    

### 2.2 两级表格结构

| 层级 | 内容 |
| --- | --- |
| 一级（订单） | Shopify订单号、子订单数、创建日期、渠道、店铺、支付状态、发货状态、商品数、标记、操作 |
| 二级（子订单） | 子订单号、商品数、仓发地、供应商、发货状态、物流单号、同步状态、操作 |

## 五、子订单列表（二级）

### 5.1 字段说明

| 字段 | 说明 |
| --- | --- |
| 子订单号 | 子订单编号，按规则自动生成，等宽字体显示 |
| 商品数 | 蓝色可点击，点击弹出商品明细弹窗 |
| 仓发地 | 国内仓/海外仓，海外仓显示编辑按钮 |
| 供应商 | 供应商名称（国内仓显示"—"） |
| 发货单状态 | 待发货/已发货/已取消 |
| 物流单号 | 发货后显示物流跟踪单号，未发货显示"—" |
| 同步状态 | 国内仓显示已同步/待同步/同步失败，海外仓显示「—」 |
| 操作 | 拆单/同步易仓/发货按钮 |

### 5.2 子订单号命名规则

**格式**：`{前缀}_{Shopify订单号}_{序号}`

| 仓发地 | 前缀 | 格式 | 示例 |
| --- | --- | --- | --- |
| 国内仓 | CN | CN\_{订单号}\_{序号} | CN\_100011838\_01、CN\_100011838\_02 |
| 海外仓 | OS | OS\_{订单号}\_{序号} | OS\_100011838\_01、OS\_100011838\_02 |

**规则说明**：

*   序号从 01 开始，两位数格式
    
*   序号递增，不重复使用
    
*   同一订单下国内仓和海外仓序号独立计算
    
*   拆单生成的新子订单继续使用当前序号递增
    

**示例**：

```plaintext
订单 #100011838 拆单后：
├── CN_100011838_01（国内仓）
├── CN_100011838_02（国内仓）
├── OS_100011838_01（海外仓/CJ）
└── OS_100011838_02（海外仓/Trendsi）

手动拆单 CN_100011838_02 后：
├── CN_100011838_02（原子订单，商品减少）
└── CN_100011838_03（新子订单，拆出的商品）

```

### 5.3 操作按钮规则

| 按钮 | 显示条件 | 说明 |
| --- | --- | --- |
| 拆单 | 发货单状态 ≠ 已发货 且 发货单状态 ≠ 已取消 | 打开手动拆单弹窗 |
| 修改仓发地 | 海外仓 且 发货单状态 = 待发货 | 海外仓改国内仓 |
| 同步易仓 | 国内仓 && 同步失败 | 单个同步到易仓系统 |
| 发货 | 海外仓 且 发货单状态 = 未发货 | 调用Shopify发货接口 |

**权限控制**：所有操作按钮均需做权限控制，无权限时按钮置灰或隐藏。

## 六、功能模块

### 6.1 手动拆单

**入口**：子订单操作列的【拆单】按钮

#### 6.1.1 前置校验规则

| 校验项 | 规则 | 错误提示 |
| --- | --- | --- |
| 拆单层级 | 仅允许对子订单执行拆单，不支持订单级拆单 | — |
| 商品校验 | 不允许将子订单内所有商品全部拆出，至少保留1件商品 | "拆单失败，至少保留1件商品" |
| 国内仓已同步校验 | 国内仓子订单且已同步易仓时，需校验易仓订单状态 | "拆单失败，易仓当前订单状态不允许拆单" |

#### 6.1.2 国内仓拆单易仓状态校验

**触发条件**：子订单仓发地=国内仓 且 同步状态=已同步

**校验逻辑**：

```plaintext
1. 调用易仓接口查询该订单状态
2. IF 易仓订单状态 = 待发货 OR 已发货:
     弹出提示："拆单失败，易仓当前订单状态不允许拆单"
     阻断操作
3. ELSE:
     继续执行拆单流程

```

**易仓订单状态与拆单权限**：

| 易仓订单状态 | 是否允许拆单 | 说明 |
| --- | --- | --- |
| 待发货 | ❌ 不允许 | 订单已进入发货流程 |
| 已发货 | ❌ 不允许 | 订单已完成发货 |
| 待处理 | ✅ 允许 | 订单未进入发货流程 |
| 已取消 | ✅ 允许 | 订单已取消 |

#### 6.1.3 拆单执行流程

**国内仓子订单（已同步易仓）**：

```plaintext
1. 校验拆分商品数量（不能全部拆出）
2. 调用易仓接口查询订单状态
3. IF 状态不允许 → 弹出错误提示，阻断
4. IF 状态允许：
   a. 调用易仓【取消订单】接口
   b. 调用Shopify【fulfillmentOrderSplit】接口执行拆单
   c. 更新原子订单商品和数量
   d. 创建新子订单
   e. 新子订单自动同步易仓
   f. 记录操作日志

```

**海外仓子订单 / 国内仓未同步**：

```plaintext
1. 校验拆分商品数量（不能全部拆出）
2. 调用Shopify【fulfillmentOrderSplit】接口执行拆单
3. 更新原子订单商品和数量
4. 创建新子订单
5. 记录操作日志

```

#### 6.1.4 弹窗流程

1.  **当前子单信息**：显示子单号、仓发地、供应商（只读）
    
2.  **选择商品**：
    
    *   卡片式展示商品图片、名称、颜色/尺码、平台SKU、内部SKU
        
    *   支持勾选商品，可设置拆分数量（≤原数量）
        
    *   全选功能
        
    *   **校验**：不允许全部拆出，至少保留1件
        
3.  **拆单预览**：显示将拆出的商品列表和目标仓发地
    

#### 6.1.5 业务规则汇总

| 规则 | 说明 |
| --- | --- |
| 拆单层级 | 仅支持子订单级拆单 |
| 商品保留 | 至少保留1件商品在原子订单 |
| 仓发地 | 跟随原子单，不可修改 |
| 国内仓已同步 | 需先校验易仓状态，满足条件先取消易仓订单再拆单 |
| 新子单同步 | 国内仓新子订单自动同步易仓 |
| 操作日志 | 拆单操作记录到订单操作日志 |
| 二次确认 | 点击确认后弹出二次提示，告知拆单结果不可逆 |

### 6.2 标记发货

**入口**：

*   子订单操作列的【发货】按钮（单个）
    
*   工具栏的【批量导入标发】按钮（批量）
    

#### 6.2.1 单个发货

**显示条件**：发货状态 ≠ 已发货 **且** 仓发地 = 海外仓

**执行逻辑**：

```plaintext
1. 点击发货按钮，弹出确认弹窗
2. 填写承运商（必填）和跟踪单号（必填）
3. 确认后调用 Shopify【fulfillmentCreate】接口
4. 接口返回成功：
   a. 更新子订单发货状态为"已发货"
   b. 更新物流单号
   c. 记录操作日志
5. 接口返回失败：
   a. 弹出错误提示
   b. 状态不变

```

**弹窗内容**：

*   子订单信息（只读）
    
*   承运商（必填，下拉选择）
    
    *   FedEx、UPS、DHL、USPS、EMS
        
    *   顺丰速运、圆通速递、中通快递、申通快递、韵达快递、其他
        
*   跟踪单号（必填）
    

#### 6.2.2 批量发货

**入口**：工具栏【批量导入标发】按钮

**说明**：支持通过Excel/CSV批量导入发货信息，调用Shopify批量发货接口

#### 6.2.3 业务规则

| 规则 | 说明 |
| --- | --- |
| 显示条件 | 仅海外仓且未发货的子订单显示发货按钮 |
| 国内仓发货 | 国内仓通过易仓系统发货，不显示发货按钮 |
| 必填项 | 承运商和跟踪单号为必填 |
| 接口调用 | 调用Shopify fulfillmentCreate 接口 |
| 操作不可撤销 | 发货后状态不可回退 |
| 物流单号 | 发货后自动更新到子订单列表 |

### 6.3 同步易仓

**单个同步**：

*   入口：子订单操作列的【同步易仓】按钮
    
*   条件：仓发地=国内仓 且 同步状态=同步失败
    

**批量同步**：

*   入口：工具栏的【批量同步易仓】按钮
    
*   自动扫描所有符合条件的子订单
    

**业务规则**：

*   同步成功后状态变为"已同步"
    
*   同步失败保持"同步失败"状态
    
*   操作记录写入操作日志
    

**修改仓发地的子订单同步规则**：

*   子订单若为手动修改仓发地（海外改国内），同步到易仓时需在易仓订单上写入备注
    
*   备注内容：`手动修改仓发地海外改国内，子订单号XXXX和子订单号XXXXX为同一个订单，不要在易仓操作合单`
    
*   目的：提示易仓操作人员不要将相关子订单合并处理

### 6.4 修改仓发地

**入口**：海外仓子订单的仓发地编辑按钮（✏️）

#### 6.4.1 功能说明

**目的**：将海外仓子订单的仓发地修改为国内仓，以便同步到易仓系统发货。

**注意**：此操作仅在履约平台修改仓发地，不涉及Shopify侧操作。

#### 6.4.2 弹窗内容

*   确认提示：`确认要修改子订单号XXXX的仓发地为国内吗？`
    
*   警示信息：`⚠️ 此操作不可逆，请确认`
    

#### 6.4.3 标记说明

手动修改仓发地的子订单，在子订单号旁显示「已改仓」标记，便于区分。

| 标记 | 样式 | 说明 |
| --- | --- | --- |
| 已改仓 | 橙色小标签 | 表示该子订单曾手动修改过仓发地 |

#### 6.4.4 业务规则

| 规则 | 说明 |
| --- | --- |
| 修改方向 | 仅允许 海外仓 → 国内仓 |
| 供应商 | 修改后供应商变为「—」（无） |
| 同步状态 | 修改后同步状态变更为「待同步」 |
| Shopify | 不操作Shopify，仅履约平台本地修改 |
| 后续操作 | 修改后需手动点击「同步易仓」按钮同步到易仓 |
| 操作日志 | 记录修改操作到订单操作日志 |

#### 6.4.4 执行流程

```plaintext
1. 点击海外仓子订单的编辑按钮
2. 弹窗显示当前信息，新仓发地固定为国内仓
3. 填写备注（选填）
4. 确认修改：
   a. 更新子订单仓发地为「国内仓」
   b. 更新供应商为「—」
   c. 更新同步状态为「待同步」
   d. 记录操作日志
5. 用户手动点击「同步易仓」按钮同步到易仓系统

```

### 6.7 批量导入标发

**入口**：工具栏【批量导入标发】按钮

#### 6.7.1 弹窗功能

| 功能 | 说明 |
| --- | --- |
| 下载模板 | 提供标准Excel模板下载 |
| 上传文件 | 支持上传 .xlsx / .csv 格式文件 |
| 数据预览 | 上传后预览导入数据，显示成功/失败数量 |
| 确认导入 | 仅成功数据可导入，失败数据需修正后重新上传 |

#### 6.7.2 导入模板字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 子订单号 | ✅ | 如 SUB-001-1 |
| 物流单号 | ✅ | 物流跟踪单号 |
| 承运商 | ✅ | FedEx/UPS/DHL等 |

#### 6.7.3 校验规则

| 校验项 | 规则 | 错误提示 |
| --- | --- | --- |
| 子订单号 | 必填，且系统中存在 | "子订单号不存在" |
| 物流单号 | 必填 | "物流单号不能为空" |
| 承运商 | 必填，需在可选范围内 | "承运商不在可选范围" |
| 子订单状态 | 必须为"待发货" | "子订单状态非待发货，不允许导入" |

#### 6.7.4 导入流程

```plaintext
1. 点击【批量导入标发】按钮，弹出导入窗口
2. 点击【下载模板】获取标准模板
3. 填写模板后点击【上传文件】
4. 系统解析文件并校验：
   a. 校验字段格式
   b. 校验子订单是否存在
   c. 校验子订单状态是否为"待发货"
5. 显示预览：
   - 成功条数（绿色）
   - 失败条数（红色）及失败原因
6. 若有失败数据，需修正后重新上传
7. 点击【确认导入】调用Shopify批量发货接口
8. 导入完成后刷新列表

```

#### 6.7.5 预览展示

| 区域 | 内容 |
| --- | --- |
| 统计区 | 导入成功 X 条 / 导入失败 Y 条 |
| 成功列表 | 子订单号、物流单号、承运商（绿色标记） |
| 失败列表 | 子订单号、失败原因（红色标记） |

| 渠道 | 订单来源渠道 |
| 店铺 | 所属店铺 |
| 支付状态 | 已支付/未支付/已退款 |
| 发货状态 | 未发货/已发货/部分发货等 |
| 子订单号 | 子订单编号 |
| 商品名称 | 商品名称 |
| 商品内部SPU | 内部SPU编码 |
| 商品内部SKU | 内部SKU编码 |
| 属性 | 颜色/尺码 |
| 仓发地 | 国内仓/海外仓 |
| 供应商 | 供应商名称 |

## 九、Shopify Webhook 对接

### 9.1 概述

系统需要对接Shopify的Webhook推送接口，用于实时接收订单和发货单的状态变更，确保履约平台数据与Shopify保持同步。

### 9.2 Webhook 事件列表

| Webhook 事件 | 触发场景 | 处理逻辑 |
| --- | --- | --- |
| `orders/cancelled` | 整单取消 | 更新订单状态为「已取消」，取消所有未发货子订单 |
| `fulfillment_orders/cancelled` | 发货单取消 | 更新对应子订单的发货单状态为「已取消」 |
| `orders/updated` | 商品取消/数量变化 | 更新订单商品数量，重新计算子订单商品数 |

### 9.3 详细处理逻辑

#### 9.3.1 整单取消（orders/cancelled）

**触发条件**：Shopify订单被取消

**处理逻辑**：

```plaintext
1. 接收 orders/cancelled webhook
2. 根据订单号查找对应订单
3. 订单标记为「已取消」（新增cancelled标记字段）
4. 发货状态保持不变
5. 遍历所有子订单：
   - 若子订单发货单状态 ≠ 已发货 → 更新为「已取消」
   - 若子订单已同步易仓 → 调用易仓取消接口
6. 记录操作日志

```

**页面展示**：

*   订单号右侧显示「已取消」红色标签
    
*   已取消的订单行显示删除线样式
    
*   整行透明度降低至60%
    

#### 9.3.2 发货单取消（fulfillment\_orders/cancelled）

**触发条件**：Shopify发货单被取消

**处理逻辑**：

```plaintext
1. 接收 fulfillment_orders/cancelled webhook
2. 根据发货单ID查找对应子订单
3. 更新子订单发货单状态为「已取消」
4. 若已同步易仓 → 调用易仓取消接口
5. 检查是否所有子订单都已取消：
   - 是 → 更新订单发货状态为「已取消」
   - 否 → 更新订单发货状态为「部分发货」或「履约中」
6. 记录操作日志

```

#### 9.3.3 商品取消/数量变化（orders/updated）

**触发条件**：订单商品被取消或数量发生变化

**处理逻辑**：

```plaintext
1. 接收 orders/updated webhook
2. 对比订单商品变化：
   - 商品被取消 → 从对应子订单中移除
   - 数量变化 → 更新子订单商品数量
3. 检查子订单商品是否为空：
   - 是 → 取消该子订单
   - 否 → 更新商品数量
4. 更新订单总商品数
5. 记录操作日志

```

### 9.4 Webhook 注册配置

| 配置项 | 值 |
| --- | --- |
| 订单取消 | `orders/cancelled` |
| 发货单取消 | `fulfillment_orders/cancelled` |
| 订单更新 | `orders/updated` |

### 9.5 数据同步规则

| 场景 | Shopify状态 | 履约平台状态 |
| --- | --- | --- |
| 订单取消 | cancelled | 已取消 |
| 发货单取消 | cancelled | 已取消 |
| 商品数量变化 | updated | 更新商品数量 |

### 9.6 异常处理

| 异常场景 | 处理方式 |
| --- | --- |
| Webhook接收失败 | 记录失败日志，支持手动重试 |
| 数据不一致 | 定时任务对比Shopify数据，自动修正 |
| 易仓取消失败 | 记录异常，人工介入处理 |
