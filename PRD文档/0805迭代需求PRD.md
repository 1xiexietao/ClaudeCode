# 0805迭代需求 PRD文档

---

## 一、变更背景

本期迭代优化拆单管理模块，调整库存驱动二次拆单的触发时间和执行规则，新增代发供应商拆单逻辑，并实现拆单后自动调用易仓审核接口锁定库存的能力。同时，采购需求管理新增采购类型字段，支持区分常规采购、备货采购、仓发邀约三种类型。

---

## 二、功能变更清单

| 序号 | 功能模块 | 变更类型 | 优先级 | 简述 |
|------|----------|----------|--------|------|
| 1 | 拆单管理-库存驱动二次拆单 | 逻辑调整 | P1 | 触发时间从7天调整为4天，子订单只能执行一次，手动拆单继承已拆状态 |
| 2 | 拆单管理-首次拆单 | 逻辑调整 | P1 | 国内发货的代发供应商按供应商维度拆单，子订单新增代发标识 |
| 3 | 拆单管理-库存驱动二次拆单 | 接口调用 | P1 | 有库存的子订单同步易仓成功后调用orderVerify接口锁定库存 |
| 4 | 拆单管理-手动拆单 | 功能新增 | P1 | 拆单弹窗新增锁定库存选项，选择锁定后同步易仓并调用审核接口 |
| 5 | 采购需求管理-采购类型 | 功能新增 | P1 | 新增采购类型字段（常规采购、备货采购、仓发邀约），支持编辑和导入 |
| 6 | 拆单管理-配送方式取值 | 逻辑调整 | P1 | 国内发货子订单同步易仓时，shipping_method_platform字段按优先级取值 |

## 三、功能详细设计

### 3.1 库存驱动二次拆单逻辑调整

#### 3.1.1 触发时间调整

| 调整项 | 调整前 | 调整后 |
|--------|--------|--------|
| 触发时间 | 订单创建满7天 | 订单创建满4天 |

#### 3.1.2 子订单执行限制

**业务规则**：

| 规则 | 说明 |
|------|------|
| 执行次数限制 | 子订单只能被执行一次库存驱动二次拆单 |
| 已拆状态标记 | 子订单执行库存驱动二次拆单后，新增的子订单（B、C）标记为「已拆」状态 |
| 任务忽略规则 | 库存驱动二次拆单定时任务执行时，忽略状态为「已拆」的子订单 |
| 手动拆单继承 | 已拆状态的子订单（B、C）如果又执行了手动拆单，新生成的子订单继承父级的「已拆」状态 |
| 继承后忽略 | 继承「已拆」状态的子订单，后续库存驱动二次拆单定时任务同样忽略 |

**数据模型变更**：

| 字段 | 类型 | 说明 |
|------|------|------|
| inventory_split_status | String | 库存驱动拆单状态：NOT_SPLIT（未拆）、SPLITTED（已拆） |
| inventory_split_time | DateTime | 库存驱动拆单执行时间 |

**执行流程**：

```
1. 定时任务扫描订单创建满4天的子订单
2. 过滤掉 inventory_split_status = SPLITTED 的子订单
3. 对符合条件的子订单执行库存驱动二次拆单
4. 拆单完成后，新生成的子订单设置 inventory_split_status = SPLITTED
5. 原子订单设置 inventory_split_status = SPLITTED
```

### 3.2 首次拆单代发供应商拆单

#### 3.2.1 代发供应商识别

**识别规则**：

| 规则 | 说明 |
|------|------|
| 识别字段 | 供应商档案的「标签」字段 |
| 判断逻辑 | 标签中包含「代发供应商」即认定为代发供应商 |
| 适用场景 | 仅用于首次拆单逻辑判断 |

#### 3.2.2 子订单代发标识

**数据模型变更**：

| 字段 | 类型 | 说明 |
|------|------|------|
| is_dropship | Boolean | 是否代发订单：true（代发）、false（非代发） |
| dropship_supplier_code | String | 代发供应商编码（is_dropship=true时填写） |

#### 3.2.3 拆单顺序规则

**拆单优先级**（保持原有顺序）：

```
第一优先级：按仓发地拆单
├── 国内发货
│   └── 第二优先级：按代发供应商拆单（标签包含「代发供应商」的供应商）
└── 海外发货
    └── 第二优先级：按供应商维度拆单
```

**拆单逻辑**：

| 仓发地 | 供应商类型 | 拆单规则 | 子订单标识 |
|--------|------------|----------|------------|
| 国内 | 代发供应商 | 按供应商拆单（同一供应商的商品在同一子订单） | is_dropship = true |
| 国内 | 非代发供应商 | 保持原有拆单规则 | is_dropship = false |
| 海外 | 所有供应商 | 按供应商维度拆单 | is_dropship = false |

### 3.3 库存驱动二次拆单调用易仓审核接口

#### 3.3.1 拆单结果分类

库存驱动二次拆单将子订单拆分为两部分：

| 分类 | 说明 | 后续处理 |
|------|------|----------|
| 有库存子订单 | 匹配到库存的子订单 | 同步易仓 → 调用orderVerify接口 |
| 无库存子订单 | 未匹配到库存的子订单 | 保持原有流程 |

#### 3.3.2 接口调用流程

**调用顺序**：

```
1. 库存驱动二次拆单完成
2. 筛选出有库存的子订单
3. 同步子订单到易仓（调用易仓同步接口）
4. 同步成功后，获取易仓返回的订单号（order_code）
5. 调用易仓审核订单接口（orderVerify）
```

**易仓审核接口参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| order_code_arr | Array | 是 | 易仓返回的订单号数组 |
| warehouse_hold_inventory | Int | 是 | 锁定库存标识：1（锁定） |

**接口调用示例**：

```json
{
  "order_code_arr": ["EC202508050001", "EC202508050002"],
  "warehouse_hold_inventory": 1
}
```

#### 3.3.3 业务规则

| 规则 | 说明 |
|------|------|
| 调用时机 | 仅针对有库存的子订单调用审核接口 |
| 调用前提 | 必须先同步易仓成功，获取到易仓订单号 |
| 锁定标识 | warehouse_hold_inventory 固定传 1（锁定库存） |
| 失败处理 | 暂不考虑异常处理，记录操作日志 |

### 3.4 手动拆单新增锁定库存选项

#### 3.4.1 功能概述

手动拆单弹窗新增「锁定库存」选项，支持用户在拆单时选择是否锁定库存。

**适用范围**：仅针对国内发货的订单

#### 3.4.2 页面交互设计

**拆单弹窗调整**：

```
┌─────────────────────────────────────────────┐
│  手动拆单                                     │
├─────────────────────────────────────────────┤
│  原子订单号：SO202508050001                    │
│                                              │
│  拆单商品选择：                                │
│  ┌─────────────────────────────────────────┐ │
│  │ ☑ SKU001  商品A  数量: 2                │ │
│  │ ☑ SKU002  商品B  数量: 1                │ │
│  └─────────────────────────────────────────┘ │
│                                              │
│  ┌─────────────────────────────────────────┐ │
│  │  拆单预览                                │ │
│  │  子订单1：SKU001 x2                     │ │
│  │    ☐ 锁定库存                           │ │
│  │  子订单2：SKU002 x1                     │ │
│  │    ☐ 锁定库存                           │ │
│  └─────────────────────────────────────────┘ │
│                                              │
│           [取消]  [确认拆单]                   │
└─────────────────────────────────────────────┘
```

**交互说明**：

| 交互项 | 说明 |
|--------|------|
| 选项位置 | 拆单预览区域，每个子订单下方显示「锁定库存」复选框 |
| 默认状态 | 默认不勾选（不锁定） |
| 选择范围 | 可针对单个或多个子订单选择锁定 |
| 适用条件 | 仅国内发货的订单显示此选项 |

#### 3.4.3 锁定库存处理流程

**处理流程**：

```
1. 用户点击「确认拆单」
2. 系统执行拆单，生成子订单
3. 检查子订单的「锁定库存」选项
4. 对于选择锁定的子订单：
   a. 同步子订单到易仓
   b. 同步成功后，调用orderVerify接口
   c. 传参：order_code_arr=[易仓订单号]，warehouse_hold_inventory=1
5. 对于未选择锁定的子订单：
   a. 正常同步易仓，不调用审核接口
```

#### 3.4.4 数据模型变更

| 字段 | 类型 | 说明 |
|------|------|------|
| warehouse_hold_inventory | Boolean | 是否锁定库存：true（锁定）、false（不锁定） |

#### 3.4.5 业务规则

| 规则 | 说明 |
|------|------|
| 适用范围 | 仅国内发货的订单 |
| 默认值 | 默认不锁定（warehouse_hold_inventory = false） |
| 锁定后处理 | 选择锁定后，同步易仓成功自动调用审核接口 |
| 接口参数 | order_code_arr = 易仓返回的订单号，warehouse_hold_inventory = 1 |

### 3.6 拆单管理-配送方式取值逻辑调整

#### 3.6.1 功能概述

国内发货的子订单同步易仓时，`shipping_method_platform` 字段的取值逻辑调整为根据订单商品的配送方式按优先级取值。

**适用范围**：仅国内发货的子订单

#### 3.6.2 取值逻辑

**映射关系**：

| 原配送方式 | 传参值 |
|-----------|--------|
| Flash shipping | 海外 |
| Standard shipping | 普通 |
| Premium shipping | 快速 |

**优先级规则**（从高到低）：

| 优先级 | 条件 | 传参值 |
|--------|------|--------|
| 1 | 订单包含「快速」配送方式 | 快速 |
| 2 | 其他情况 | 普通 |

#### 3.6.3 示例说明

| 订单包含的物流方式 | 传参值 | 说明 |
|-------------------|--------|------|
| 只有海外 | 普通 | 无快速，默认普通 |
| 海外 + 普通 | 普通 | 无快速，默认普通 |
| 海外 + 普通 + 快速 | 快速 | 有快速，传快速 |
| 海外 + 快速 | 快速 | 有快速，传快速 |

#### 3.6.4 业务规则

| 规则 | 说明 |
|------|------|
| 适用范围 | 仅国内发货的子订单 |
| 取值依据 | 订单商品的配送方式（非订单级） |
| 优先级逻辑 | 有「快速」传「快速」，否则传「普通」 |
| 字段位置 | 同步易仓接口参数 `shipping_method_platform` |

### 3.5 采购需求管理-采购类型

#### 3.5.1 功能概述

采购需求管理新增「采购类型」字段，用于区分不同来源和用途的采购需求。**原「仓发邀约标签」功能合并到采购类型字段中**，不再单独维护仓发邀约标签。

**适用范围**：
- ✅ **采购需求**：显示采购类型字段，完成下单时校验必填
- ❌ **生产需求**：不显示采购类型字段

**采购类型枚举**：

| 采购类型 | 说明 | 与原仓发邀约标签关系 |
|----------|------|---------------------|
| 常规采购 | 系统自动创建的采购需求，默认类型 | 原无仓发邀约标签的需求 |
| 备货采购 | 手动创建或批量导入的备货需求 | 原无仓发邀约标签的需求 |
| 仓发邀约 | 仓发邀约Agent生成的需求 | 原有仓发邀约标签的需求 |

#### 3.5.2 字段位置

采购类型字段位于「收货地址」下方，为订单维度字段。

**页面展示**：

```
┌─────────────────────────────────────────────┐
│  采购需求详情                                 │
├─────────────────────────────────────────────┤
│  需求单号：PR202508050001                     │
│  ...                                         │
│  收货地址：广东省深圳市xxx                    │
│  ┌─────────────────────────────────────────┐│
│  │ 采购类型：[常规采购 ▼]                   ││
│  └─────────────────────────────────────────┘│
│  ...                                         │
└─────────────────────────────────────────────┘
```

#### 3.5.3 默认值规则

| 创建方式 | 默认采购类型 | 说明 |
|----------|-------------|------|
| 系统自动创建 | 常规采购 | 包括缺货计算、销一采一等自动生成的需求 |
| 仓发邀约Agent生成 | 仓发邀约 | 仓发邀约流程自动创建的需求 |
| 手动创建 | 空（需手动选择） | 用户需手动选择采购类型 |

#### 3.5.4 特殊规则

| 规则 | 说明 |
|------|------|
| 自研款 | 自研款商品没有采购类型，采购类型字段不显示 |
| 编辑权限 | 采购需求管理-编辑页面支持手动选择采购类型 |
| 仓发邀约标签合并 | 原「仓发邀约标签」功能废弃，统一使用「采购类型」字段标识仓发邀约需求 |

#### 3.5.5 仓发邀约标签迁移说明

**背景**：原系统中存在独立的「仓发邀约标签」字段用于标识仓发邀约Agent生成的需求，本次迭代将该功能合并到「采购类型」字段中，实现统一管理。

**迁移规则**：

| 场景 | 处理方式 |
|------|----------|
| 原有仓发邀约标签的需求 | 采购类型自动迁移为「仓发邀约」 |
| 原无仓发邀约标签的需求 | 采购类型保持为「常规采购」或「备货采购」 |
| 新建需求 | 按新规则自动填充采购类型 |

**字段映射**：

| 原字段 | 新字段 | 映射规则 |
|--------|--------|----------|
| 仓发邀约标签 = 有 | purchase_type = WAREHOUSE_INVITE | 直接迁移 |
| 仓发邀约标签 = 无 | purchase_type = NORMAL/STOCK | 根据创建方式判断 |

**业务影响**：
- 原「仓发邀约标签」筛选条件改为「采购类型 = 仓发邀约」
- 原「仓发邀约标签」展示列改为「采购类型」列
- 仓发邀约Agent生成的需求，采购类型自动设为「仓发邀约」

#### 3.5.6 数据模型变更

**需求单表新增字段**：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| purchase_type | String | NULL | 采购类型：NORMAL（常规采购）、STOCK（备货采购）、WAREHOUSE_INVITE（仓发邀约） |

**原字段处理**：

| 原字段 | 处理方式 |
|--------|----------|
| 仓发邀约标签 | 废弃，不再使用。数据迁移到 purchase_type 字段 |

**字段说明**：

| 字段 | 写入时机 | 使用场景 |
|------|----------|----------|
| purchase_type | 需求单创建时 | 标识采购类型，用于列表展示和筛选 |
| purchase_type | 编辑页面手动修改 | 支持手动调整采购类型 |
| purchase_type | 数据迁移时 | 原仓发邀约标签迁移写入 |

#### 3.5.6 业务规则

| 规则 | 说明 |

| 自动创建默认值 | 系统自动创建的采购需求，默认为「常规采购」 |

| 自研款处理 | 自研款商品不显示采购类型字段，该字段为空 |
| 编辑支持 | 采购需求管理-编辑页面支持手动选择采购类型 |
| 列表展示 | 采购需求列表新增「采购类型」列展示 |

| 采购单继承 | 采购单的采购类型从关联的需求单继承 |
