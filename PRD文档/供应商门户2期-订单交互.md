## 一、需求背景

为梳理采购订单（PO）从创建、确认、发货、收货的全生命周期管理需求，明确供应商门户与关联系统的系统边界，解决采购协同中沟通效率低、人工操作多、状态同步不及时等问题，优化供应商与企业内部的协同效率，降低跨角色、跨系统的沟通成本，特搭建并优化供应商门户系统。

## 二、产品目标

1. 实现采购订单全生命周期的数字化、标准化管理，打通从采购需求生成到订单入库的全流程数据链路。
2. 自动化生成采购需求，减少人工提报的操作成本，提升需求生成的准确性和及时性。
3. 精细化管理采购单状态，实现企业内部与供应商门户的状态实时同步，消除信息差。
4. 完善供应商门户的操作功能与预警通知机制，提升供应商接单、发货等操作的响应效率。
5. 建立标准化的采购申请审核流程，实现修改数量、缺货等申请的线上化处理与追溯。

## 三、关联系统与数据来源

### 3.1 关联系统

供应商门户系统与**订单履约平台**、**易仓ERP**深度联动，实现数据互通、状态同步；同时通过对接**Shopify独立站订单**，获取核心业务数据。

### 3.2 数据来源

核心数据为**Shopify 动销订单**，作为采购需求生成的唯一基础数据来源；可用库存数据以易仓 ERP 为准，、在途以订单履约未完结需求单为准，且在生成采购需求前会主动执行库存更新动作。

## 四、核心功能模块

本次供应商门户的核心功能模块包含：

1. 采购需求管理（含需求生成、计算、转采购单）
2. 采购单管理（含状态变更、审核、预警、撤销）
3. 供应商门户采购订单管理（含供应商操作、状态展示、日志追溯）
4. 供应商列表管理（含门户接单开关配置、新增三个基础字段）
5. 预警配置管理（含时效配置、生成需求时间配置）
6. 消息通知管理（含钉钉群通知）
7. 采购员负责供应商配置（新增负责供应商绑定）
8. 外部商品图包同步规则优化
9. 操作日志结构优化

## 五、详细功能设计

### 5.1 采购需求管理

采购需求管理为采购单生成的前置环节，实现采购需求的自动化、手动化生成，以及需求单到采购单的转化，同时定义需求相关的核心计算逻辑。

#### 5.1.1 需求自动生成前置条件

系统 **仓储设置（默认仓库、收件人 / 地址 / 电话）** 未完成配置时或者供应商备货主体、收款人、税率任一字段未填写，允许自动生成采购需求单，生成后不自动完成需求并自动同步到门户-采购订单

#### 5.1.2 需求自动生成触发方式

1. **定时触发**：每天定时聚合 Shopify 动销订单数据，自动生成需求单，生成前**主动执行一次易仓 ERP 库存更新动作**，确保库存数据为最新。
   1. 采购需求：按照商品类型（POD/现货）生成采购需求单，不需要根据供应商拆分生成采购需求
   2. 外部采购需求：按供应商维度拆分生成外部采购需求单
2. 每天定时聚合时间取需求基础配置-需求自动创建时间
3. **手动触发**：提供手动触发生成需求单的按钮，**按钮做权限控制**，仅用于企业内部测试或特殊业务场景；
   - 触发规则：每次点击均根据**最新的 Shopify 动销订单**重新生成；
   - 重复控制：基于最新订单数据生成，避免重复创建相同需求单。

#### 5.1.3 需求生成规则

提供两种可选生成方案，根据业务需求确认方案：

1. ~~**方案一（销一采一）**~~：根据前一天的 Shopify 动销订单直接生成需求单，有多少订单则采购对应数量的商品。
2. **方案二（缺货计算）**：通过计算商品缺货数量生成采购需求单，核心计算公式为：**缺货数量 = 需求数量 - 可用库存 - 在途**；
   - 边界兜底：若计算结果为**负数和为0**（即可用库存 + 在途≥需求数量），对该 SKU**直接不生成需求单**，无额外日志记录与提醒。

#### 5.1.4 核心数据计算逻辑

| 数据项 | 计算/定义规则 |
| --- | --- |
| 需求数量 | 订单支付状态为已支付 **且**（发货状态为未发货/部分发货）的SKU数量 |
| 可用库存 | 易仓ERP中的可用库存（易仓库存记录已经有了），包含可售库存+待出库库存（生成需求前主动更新）【取默认仓库的可用库存】 |
| 在途数量 | 履约平台中所有需求SKU状态为待确认+待下单+待接单+已接单+进行中的SKU数量 |
| 缺货数量 | 需求数量 - 可用库存 - 在途数量，结果为0和负则不生成该 SKU 需求 |

#### 5.1.5 需求生成范围与供给方式

1. **排除规则**：SPU商品状态为海外仓 or 供给方式为AIGC，满足其中一个都不自动创建采购需求。
2. **供给方式**：根据订单内的商品内部开款的商品生成采购需求，外部商品生成外部采购需求（SPU编码30开头）

#### 5.1.6 自动生成需求的默认字段

系统自动生成需求单（包含采购需求+外部采购需求）时，默认填充以下字段，字段值从对应系统配置中获取，若有字段无配置则为空，需求单状态默认为待确认：

| 默认字段 | 取值规则 |
| --- | --- |
| 销售渠道 | 独立站-shopify |
| 备货主体 | 供应商列表 - 备货主体配置 |
| 采购员 | 采购策略配置-采购/跟单人设置 |
| 收款人 | 供应商列表 - 收款人配置 |
| 采购仓库 | 仓储设置-仓库管理-默认仓库 |
| 收件人-电话 | 仓储设置-收件人设置-默认收件人电话 |
| 收件人-地址 | 仓储设置-收件人设置-默认收件人地址 |
| 税率 | 供应商列表 - 税率配置 |
| 期望货期 | 需求基础配置-预计货期配置 |

POD商品的采购需求：供应商和收款人字段留空

现货商品非1688采购：优先取sourceType: 10的supplierName字段，收款人自动获取对应供应商的系统配置，系统无该供应商则收款人字段留空

现货商品1688采购：优先取sourceType: 10的supplierName字段，收款人取alibaba-product-info

接口alibabaSupplierName字段，切换成否1688采购时留空

采购需求-采购账号取值逻辑：取应用名称=1688BatchOrderMuseTech，有默认值拿默认，无默认按创建时间拿第一个

#### 5.1.7 采购需求单转采购单规则

1. 在系统内确认采购需求后，系统**按供应商+采购员+是否1688采购维度**自动生成采购单。
2. 外部采购需求，**供应商+采购员+收款人**
3. 需求单创建后，后续库存 / 在途数据变化**不会导致采购数量自动变为 0**，确保采购单生成的有效性。

#### 5.1.8 自动生成的外部采购需求自动下单逻辑

自动生成的外部采购需求&&必填字段都有数据自动完成下单，根据供应商是否开启门户接单，区分采购单状态及同步规则：

1. 必填字段说明：销售渠道、备货主体、采购仓库、收件人-电话、收件地址、收款人、采购员、需求数量、税率、下单价（外部取供货价、采购需求取参考单价）、总金额（需求数量*下单价）、期望货期
   1. 只要上述一个字段无数据，则此需求单不自动完成下单
2. 外部采购需求 **且** 供应商列表开启门户接单：下单后且采购单自动同步至供应商门户采购订单后采购单状态为**进行中-待接单**。
3. 外部采购需求 **且** 供应商列表未开启门户接单：下单后采购单状态为**待采购**，不向供应商门户同步。

#### 5.1.9 采购需求单完结后门户订单状态更新

当（采购需求+外部采购需求）需求单内当前的SKU状态变更为已完结（排除已终止）时，系统根据**入库数量和退货数量**，更新供应商门户中对应采购订单的状态，规则为：

1. **已入库**：需求数量 = 实际入库数量(入库数量-退货数量)。
2. **部分入库**：需求数量 ≠ 实际入库数量(入库数量-退货数量)。
3. 存在一个SKU多个采购单的场景，会出现采购单PO1已完结、PO2进行中、PO3已终止，
   1. 根据数量判定状态，每次需求SKU状态变更为已完结时，都触发判定
   2. 需求数量-已终止数量=实际入库数量(入库数量-退货数量)，判定为已入库
   3. 需求数量-已终止数量≠  实际入库数量 (入库数量-退货数量)，判定为部分入库
4. 若采购订单状态为部分发货，则不修改采购订单状态，只更新采购订单商品明细的实际入库数量和退货数量，以上操作只针对已发货状态的采购订单
5. 并同步更新采购订单商品明细的实际入库数量（需求单SKU入库数量-退货数量）和退货数量

#### 5.1.10 采购需求单内SKU明细，支持单个SKU多个采购单号

因支持供应商部分发货，会出现同一个SKU分多次发货的场景，需求明细要支持单个SKU多个采购单号

1. （采购需求+外部采购需求）采购需求详情的数据展示维度在加上采购单号维度，若单个SKU有两个采购单号，那展示就是2条数据

### 5.2 采购单管理

采购单管理为企业内部核心操作模块，优化了采购单状态体系，新增多类审核流程、标签预警及操作权限，**所有状态变更均明确边界场景，无模糊触发条件**，且采购员可查看企业内所有采购单，无数据范围限制。

#### 5.2.1 采购单状态体系调整

优化原有采购单状态，新增适配供应商门户协同的状态，原状态与现状态对比如下，所有状态均为互斥状态，无同时生效可能：

| **原采购单状态** | **现采购单状态** |
| --- | --- |
| 待采购 | 待采购 |
| 审核中 | 审核中 |
| 采购异常 | 采购异常 |
| 进行中 | 进行中-待接单、进行中-待发货、进行中-同步异常 |
| 已完成 | 已完成 |
| 已撤销 | 已撤销 |

#### 5.2.2 采购单状态核心调整逻辑

1. **原1688采购单**：向1688下单后，采购单状态从原"进行中"调整为**进行中-待发货**。
2. **物流单号相关**：原采购单录入物流单号后（包含1688采购单和非1688采购单），创建入库通知并自动同步至易仓ERP；若同步易仓ERP失败，采购单状态从原"进行中"调整为**进行中-同步异常**。
3. **非1688采购单（供应商未开启门户接单）**：新增该类采购单时，状态默认为**待采购**。
4. **非1688采购单（供应商开启门户接单）**：同步供应商门户成功则状态为**进行中-待接单**；同步门户采购订单失败则状态为**待采购**。
5. **部分发货→自动拆分采购单逻辑**
   1. 触发条件：供应商在门户操作发货，满足任一条件即判定**部分发货**：
      1. 未勾选采购单内**全部商品**；
      2. 勾选商品的**发货数量 ＜ 采购数量**；
      3. 触发后**系统自动执行采购单拆分**，无人工操作。
   2. 拆单规则（已发货留原单，未发货拆新单）
      1. **原采购单（已发货部分）**
         1. 商品 / 数量：固定为供应商**实际发货的商品明细 + 对应发货数量**，与门户提交的发货信息完全一致；
         2. 基础信息：保留原采购单所有核心信息（采购单号、供应商、备货主体、收款人、税率、采购员、期望货期等），不做任何修改；
         3. 自动操作：拆单后立即为原采购单**创建入库通知单**，并**实时同步至易仓 ERP**；
         4. 状态判定：同步易仓成功→原采购单状态更新为**已完成**；同步易仓失败→原采购单状态更新为**进行中 - 同步异常**（仅支持人工手动重试同步，重试成功后更新为已完成）；
         5. 履约规则：原采购单拆单后超时标签（接单超时、发货超时）立即清空，原单不再接受任何发货、修改等操作，仅支持查看详情、操作日志。
      2. **新采购单（未发货部分）**
         1. 商品 / 数量：为原采购单剩余未发货的商品明细 + 对应剩余数量（原数量 - 已发货数量）；
         2. 基础信息：完全继承原采购单的所有核心基础信息（供应商、备货主体、收款人、税率、采购员、采购仓库、期望货期等），与原单保持一致；
         3. 状态设定：新采购单生成后，状态直接更新为进行中 - 待发货；
         4. 同步规则：新采购单生成后实时同步至供应商门户，门户-采购订单按部分发货展示，支持供应商后续操作继续发货；
         5. 履约规则：新采购单为独立履约单元，后续发货（全部 / 部分）均按正常采购单规则执行，若再次部分发货则重复触发拆单逻辑（新单再拆新单）。
   3. 拆单后数据联动规则（需求单）
      1. 采购单拆单后需求单内SKU数量与采购单关系都需要联动拆分
         1. 如SKU1000001采购数量10，对应采购单号PO1，供应商部分发货数量7，采购单自动拆分成PO1和PO2,PO1原采购单（已发货部分），PO2新采购单（未发货部分）联动变更需求单内
            1. SKU1000001采购数量7，对应采购单PO1
            2. SKU1000001采购数量3，对应采购单PO2

#### 5.2.3 待采购状态特殊操作

采购单处于**待采购**状态时，系统提供**手动同步门户按钮**，支持人工触发向供应商门户的同步操作；同步失败后无任何限制，可随时再次手动触发。

- 同步的前置条件：采购单对应供应商列表列表开启门户接单开关 && 非1688采购单
- 后置条件：门户-采购订单创建采购订单初始状态未待接单，采购单状态变更为进行中-待接单

#### 5.2.4 采购单标签预警

新增两类超时标签，触发生成标签的采购单，需发送钉钉群通知，标签生成规则：

1. **接单超时标签**：当前时间 - 采购单同步门户的时间 > 系统配置的**接单时效**。
2. **发货超时标签**：当前时间 - 采购单同步门户的时间 > 系统配置的**发货时效**。
3. **标签清除**：供应商后续完成接单 / 发货操作后，标签**自动清除**；操作日志中会记录标签生成与清除的时间，无手动清除功能。
4. 采购单列表，采购单号列显示红色超时标签

#### 5.2.5 采购单审核流程

新增线上审核流程，审核规则明确：

- ~~**修改数量审核**~~：审核通过后，联动修改采购单的商品数量和需求单的对应商品数量；审核驳回则保持原数据不变。
- **缺货审核**：
  - **部分商品缺货 → 审核通过**
    - 供应商门户 - 采购订单（后置条件）
      - 采购订单状态**变更为「待接单」**（仅缺货商品做标记，不影响可发货商品）；
      - 订单商品栏：**缺货 SKU 标记「缺货已审核」**，置灰不可操作发货；可正常发货 SKU 保持可操作；
      - 操作日志记录：`部分商品缺货审核通过，SKU：XXX 缺货作废，剩余商品可正常接单`。
    - 订单履约平台 - 采购单（后置条件）
      - **自动执行拆单**（严格沿用上面拆单规则：已发货留原单，缺货拆出作废）：
      - 原采购单：保留**可正常发货的商品 / SKU**，状态维持「进行中 - 待接单」；
      - 拆分新采购单：仅包含**缺货商品 / SKU**，状态直接变为「已撤销」，撤销原因：供应商申请缺货审核通过，撤销备注：缺货申请审核通过，采购单自动撤销；
      - 禁止缺货 SKU 后续任何履约、发货、入库操作；
    - 关联需求单（后置条件）
      - 需求单**不整单撤销**，仅**缺货对应 SKU 状态变为「已终止」，终止原因：**供应商申请缺货审核通过；
      - 可正常发货的 SKU 状态**保持原待履约状态**；
      - 需求单总状态维持进行中，仅标记部分 SKU 作废。
    - 库存 & 商品下架（后置条件）
      - 仅**缺货的 SKU**：自动更新供应商门户库存并自动触发库存为0同步商品运营的流程；
  - **全部商品缺货 → 审核通过（整单作废）**
    - 供应商门户 - 采购订单（后置条件）
      - 订单状态直接变为「已撤销」；
      - 全单商品标记「整单缺货审核通过，已撤销」，所有按钮隐藏（仅查看日志）；
      - 操作日志记录：全部商品缺货审核通过，整单已撤销。
    - 订单履约平台 - 采购单（后置条件）
      - 采购单状态直接变为「已撤销」；
      - 整单终止所有流程，不拆单、不生成入库单、不同步易仓；
      - 标记关单原因：供应商全部商品缺货，审核通过撤销。
    - 关联需求单（后置条件）
      - 需求单所有 SKU 状态同步变为「已终止」；
      - 需求单总状态变为「已终止」，整单终止履约；
      - 标注原因：关联采购单全部商品缺货，审核通过撤销。
    - 库存 & 商品下架（后置条件）
      - 订单内所有 SKU：自动更新门户库存、同步库存到POP；
    - 后续履约规则（后置条件）
      - 整单彻底终止，供应商无任何操作权限；
      - 若需重新采购，必须新建需求单 + 采购单。
  - **审核驳回，采购订单状态变回待接单，采购单状态变更为进行中-待接单**
- **通用审核规则**：驳回时**必须强制采购人员填写驳回原因**（无字符数限制），驳回原因同步至供应商门户并做醒目展示；**不设置采购人员审核时效，无超时未审核的自动处理规则**。

#### 5.2.6 采购单自动关闭规则

系统支持配置**关单时间（X 小时）**，自动关闭规则**仅针对待采购、审核中、进行中-待接单、进行中-待发货&&非1688采购的采购单**（对应门户状态「待接单」「审核中」「待发货」「部分发货」），其他状态不触发自动关闭：

- 触发条件：当前系统时间 - 采购单同步至供应商门户的时间 ＞ 关单时效配置（X 小时），系统自动触发关单流程。
- 状态变更：触发后采购单状态自动变更为**已撤销**，无自动恢复功能，需人工重新创建。
- **关单时效配置**：沿用「预警配置管理」中的「关单配置时间（X h）」参数，由系统管理员统一配置（单位：小时），配置后全局生效。
- 自动关单状态同步链路
  - **第一步：供应商门户采购订单状态变更**
    - 触发关单后，门户订单状态从「待接单」「待发货」直接变更为「已取消」；
    - 「部分发货」状态变为已发货，并触发状态判断，
      - 已发货部分对应的需求所有SKU状态若为已完结，则根据采购订单的采购数量-关单数量=对应需求所有SKU实际入库数量，则判定采购订单订单状态为已入库
      - 若不相等，则判定采购订单状态为部分入库/已退货
    - 门户订单详情页标注关单原因：「自动关单：超时未发货（关单时效 X 小时）」，关单时间同步记录。
    - 若采购单没有同步到门户，直接跳过第一步到第二步
  - **第二步：订单履约平台采购单状态同步**
    - 门户状态变更后，实时同步至订单履约平台，采购单状态从「进行中 - 待接单」/「进行中 - 待发货」变更为「已撤销」；
    - 若采购单已拆单（部分发货后生成新采购单），则拆分后的**采购单**同步触发自动关单，状态均变更为「已撤销」；
    - 操作日志记录：「系统自动关单，备注：超时未发货（关单时效 X 小时）」。
  - **第三步：需求单及对应 SKU 状态同步**
    - 履约平台采购单状态变更为「已撤销」后，关联的需求单（及对应 SKU）状态同步变更为「已终止」；
    - 若需求单内单个 SKU 关联不同采购单，仅**该关单采购单对应的 SKU**状态变更为「已终止」，其他 SKU 状态保持不变；
    - 终止原因为：超时未发货，系统自动关单
  - 触发钉钉群通知

#### 5.2.7 采购人员操作权限（按采购单状态）

1. **进行中 - 待接单**：支持采购人员发起**修改数量申请**、支持采购人员**撤销采购单，**撤销审核通过后供应商门户订单状态同步为已取消。
2. **进行中 - 待发货**：支持采购人员**撤销采购单**，撤销审核通过后供应商门户订单状态同步为已取消。
3. **数据查看**：采购员可查看企业内部**所有采购单**，无供应商 / 品类 / SKU 维度的查看范围限制；采购员离职 / 调岗时，其负责的未完结采购单可直接由其他采购员操作，无需批量转移。
4. 修改数量申请的功能与后置条件基本与待采购状态的一致
   1. 区别
      1. 修改数量审核通过后，还需要联动修改门户-采购订单内的数量和采购订单状态变更为待接单，采购单状态变更为进行中-待接单
5. 撤销采购单的功能和后置条件
   1. 审核通过后，与采购单自动关单的后置条件基本一致，参考上面5.2.6

#### 5.2.8 采购单审核通知

当有新的采购单状态变更为**审核中**时，系统自动发送**钉钉群通知**，提醒相关审核人员处理；通知仅做通用提醒，**无需标注具体 SKU 信息，跳转链接至采购单列表页即可**。

#### 5.2.9 供应商发起的审核类型

供应商在门户端发起的申请，同步至企业内部后均触发对应审核，包括供应商~~修改数量审核~~、供应商缺货审核；**供应商申请被驳回后，重新发起任意类型申请均无时间间隔与次数限制**，系统不做任何管控。

### 5.3 供应商门户采购订单管理

该模块为供应商操作的核心模块，包含采购订单状态管理、订单列表、订单操作、倒计时功能、订单详情页等子功能，实现供应商对采购订单的全流程线上操作。

#### 5.3.1 采购订单状态体系

供应商门户的采购订单状态与企业内部订单履约平台状态实时同步，共7类核心状态，各状态的触发条件、可操作按钮及说明如下：

| 订单状态 | 触发条件 | 可操作按钮 | 状态说明 |
| --- | --- | --- | --- |
| 待接单 | 1. 订单履约平台采购单状态变为"进行中-待接单"并同步至供应商门户；<br>2. 各类申请审核通过/驳回后，状态还原至待接单 | 接单、申请缺货、~~发起修改数量申请~~、查看详情、查看日志 | 对应履约平台"进行中-待接单"初始状态，供应商未确认承接，采购单已同步，页面显示**接单倒计时** |
| 审核中 | 供应商在待接单状态下发起任意类型申请（缺货~~、修改数量~~），提交成功并同步至履约平台后 | 取消申请、查看详情、查看日志 | 对应履约平台"审核中"状态，含二种申请类型，详情页标注具体类型；不可接单、发起其他申请 |
| 已接单 | 供应商成功操作接单后，同步至订单履约平台 | 发货、查看详情、查看日志 | 对应履约平台"进行中-待发货"，供应商确认承接，需按约定交货期发货，页面显示**发货倒计时** |
| 部分发货 | 供应商操作发货时，**未全部选中商品或发货数量小于采购数量**，提交成功并同步至履约平台后 | **继续发货**、查看详情、查看日志 | 履约平台自动拆单，触发自动生成入库通知并自动同步到易仓，若同步成功则采购单状态变更为"已完成"，若同步失败者采购单状态变更为"进行中-同步失败"，供应商仅完成部分商品发货，页面显示**剩余商品发货倒计时**；可多次操作继续发货，直至完成全部商品发货 |
| 已发货 | 供应商操作发货时，**全部选中商品且发货数量等于采购数量**（或部分发货后完成剩余商品发货），提交成功并同步至履约平台后 | 查看详情、查看日志 | 履约平台触发自动生成入库通知并自动同步到易仓，若同步成功则采购单状态变更为"已完成"，若同步失败者采购单状态变更为"进行中-同步失败"，供应商已完成发货，等待企业仓库入库验收 |
| 已入库 | 订单履约平台接收入库信息（实际入库数量=采购数量），状态变为"已完成"并同步至供应商门户 | 查看详情、查看日志 | 采购单全部入库完成，订单履约结束 |
| 部分入库/已退货 | 订单履约平台接收入库信息（部分入库），并同步至供应商门户 | 查看详情、查看日志 | 含部分入库、已退货两种场景，详情页标注具体场景，后续由企业与供应商协商处理 |
| 已取消 | 采购人员在订单履约平台取消采购单（状态变为"已撤销"），同步至供应商门户后 | 查看详情、查看日志 | 对应履约平台"已撤销"，采购单被取消，取消原因同步至供应商门户 |

#### 5.3.2 采购订单列表

为供应商展示名下所有同步的采购单，支持多维度筛选、搜索、排序及功能操作，**订单数据永久保存**，供应商可随时查看所有历史订单（含已入库、已取消）：

1. **展示范围**：供应商名下所有已从履约平台同步至门户的采购单，无数据留存时效限制。
2. **筛选功能**：支持按**订单状态、**供应商(非供应商账号才显示)**、下单时间**筛选。
3. **展示字段**：采购订单号、创建日期、供应商名称、采购单号、商品数量（SKU数量和订单总数量）、订单金额（不含税）、订单状态、商品名称、商品图片、SPU 货号、SKU 货号、SKU编码（内部SKU条码）、颜色 / 尺码、采购数量、下单价格、小计（不含税）、接单倒计时（仅待接单显示）、发货倒计时（仅已接单/部分发货后显示）、接单超时文字(仅待接单 && 接单超时显示)、发货超时文字(仅已接单/部分发货 && 接单超时显示)、超时自动关单文字(采购订单存在超时部分关单/超时全部关单都显示)、操作按钮（按订单状态动态显示）。
   1. 内部商品不用展示SPU货号、SKU货号
4. **展示维度**：按采购订单维度展示，支持展开查看采购订单内的商品明细。
5. **排序功能**：默认按下单日期**倒序**排序。
6. **搜索功能**：支持按**商品名称、SPU货号、SKU货号、采购单号、下单日期**搜索。
7. **功能按钮**：提供**导出**、**打印SKU条码**按钮，支持批量操作。

#### 5.3.3 采购订单核心操作按钮功能

所有操作均需做权限及状态校验，操作后同步至企业内部订单履约平台，核心操作的场景、流程、约束如下：

##### 5.3.3.1 接单

- **操作场景**：仅采购单状态为"待接单"时可操作；审核中状态不可操作，申请审核通过/驳回后回归待接单可正常操作。
- **操作流程**：供应商点击"接单"按钮 → 系统弹出确认弹窗（提示"确认承接该采购单？接单后需按约定交货期发货"） → 供应商确认 → 系统记录接单时间、操作人 → 更新订单状态为"已接单" → 同步至履约平台（采购单状态变为进行中-待发货） → 弹窗提示"接单成功"。
- **约束条件**：同一采购单仅可接单一次；接单后不可发起任何申请；接单后自动启动**发货倒计时**。

##### 5.3.3.2 缺货申请

- **操作场景**：仅采购单状态为"待接单"时可操作。
- **操作流程**：供应商点击"缺货申请"按钮 → 填写缺货申请表单（必填：缺货商品明细、缺货原因；） → 供应商确认提交 → 系统校验 → 记录申请时间、操作人、申请内容 → 更新订单状态为"审核中" → 同步申请信息至履约平台（采购单状态变为审核中） → 弹窗提示"申请提交成功，等待审核"，返回订单详情页可查看进度。
- **约束条件**：同一采购单同一时间仅可发起一种类型申请；申请提交后未审核完成前，不可修改内容、不可发起其他申请、不可接单；审核通过 / 驳回后，可无限制重新发起任意类型申请。

##### 5.3.3.3 修改数量申请

- ~~**操作场景**~~：仅采购单状态为"待接单"时可操作。
- ~~**操作流程**~~：供应商点击"修改数量申请"按钮 → 填写修改数量申请表单（显示当前采购数量，必填：申请修改后数量、修改原因） → 供应商确认提交 → 系统校验 → 记录申请信息 → 更新订单状态为"审核中" → 同步申请信息至履约平台（采购单状态变为审核中） → 弹窗提示"申请提交成功，等待审核"，返回订单详情页可查看进度。
- ~~**约束条件**~~：与缺货申请约束条件一致。

##### 5.3.3.4 取消申请

- **操作场景**：仅采购单状态为"审核中"时可操作。
- **操作流程**：供应商点击"取消申请"按钮 → 系统弹出确认弹窗 → 供应商确认 → 系统记录取消操作信息 → 更新订单状态为"待接单" → 同步至履约平台（采购单状态还原为进行中-待接单） → 弹窗提示"申请取消成功"。
- 供应商只能直接发起的缺货申请，由内部采购人员发起的修改数量和撤销供应商不能撤销

##### 5.3.3.5 发货

- **操作场景**：仅采购单状态为"已接单"时可操作。
- **操作流程**：
  1. 供应商点击 "发货 /" 按钮 → 进入发货表单页面，**展示采购单商品明细、采购数量**；
  2. 供应商勾选需发货的商品，填写对应发货数量（支持手动输入，≤剩余采购数量）、物流单号、物流公司；
  3. 供应商确认提交 → 系统**自动判定发货类型**：
     1. 部分发货：若**未勾选全部商品**或**填写的发货数量总和＜采购单总数量** → 系统更新订单状态为**部分发货** → 同步发货信息至履约平台（触发入库通知单自动创建并同步易仓，根据同步结果更新采购单状态为"进行中-部分发货"或"进行中-同步失败"） → 弹窗提示 "部分发货提交成功，可继续发货"；
     2. 已发货：若**勾选全部商品**且**填写的发货数量总和 = 采购单总数量** → 系统更新订单状态为**已发货** → 同步发货信息至履约平台（触发入库通知单自动创建并同步易仓，根据同步结果更新采购单状态为"已完成"或"进行中-同步失败"） → 弹窗提示 "全部发货提交成功，等待仓库入库"；
  4. 系统记录发货时间、操作人、发货商品明细、已发货数量、剩余发货数量、物流信息，同步至操作日志。
- **核心规则**
  1. 发货数量校验：手动输入的发货数量仅允许为正整数，≤对应商品的剩余发货数量，超出则前端拦截并提示 "发货数量不可超过剩余数量"；
  2. 多次部分发货：支持供应商对同一采购单进行多次部分发货，每次发货后系统更新已发货 / 剩余发货数量，直至完成全部发货；
  3. 倒计时规则：部分发货状态下，**发货倒计时针对剩余未发货商品继续生效**，超时则触发钉钉群通知采购人员。
  4. 部分发货同步给履约平台后，履约平台需自动拆单，拆单逻辑请看5.22

##### 5.3.3.6 继续发货

- **操作场景**仅采购单状态为**部分发货**时可操作，每次操作均针对**剩余未发货商品 / 数量**。
- **操作流程**：
  1. 供应商点击 "继续发货" 按钮 → 进入发货表单页面，**展示采购单商品明细（分为已完全发货商品和待发货商品）、采购数量、已发货数量、剩余发货数量**；
  2. 供应商勾选需发货的商品，填写对应发货数量（支持手动输入，≤剩余发货数量）、物流单号、物流公司；
  3. 供应商确认提交 → 系统**自动判定发货类型**：
     1. 部分发货：若**未勾选全部商品**或**填写的发货数量总和＜采购单总数量** → 系统更新订单状态为**部分发货** → 同步发货信息至履约平台（采购单状态变为进行中 - 部分发货，触发入库通知单自动创建） → 弹窗提示 "部分发货提交成功，可继续发货"；
     2. 已发货：若**勾选全部商品**且**填写的发货数量总和 = 采购单总数量** → 系统更新订单状态为**已发货** → 同步发货信息至履约平台（采购单状态变为进行中 - 待发货，触发入库通知单自动创建） → 弹窗提示 "全部发货提交成功，等待仓库入库"；
  4. 系统记录发货时间、操作人、发货商品明细、已发货数量、剩余发货数量、物流信息，同步至操作日志。
- **核心规则**
  1. 发货数量校验：手动输入的发货数量仅允许为正整数，≤对应商品的剩余发货数量，超出则前端拦截并提示 "发货数量不可超过剩余数量"；
  2. 多次部分发货：支持供应商对同一采购单进行多次部分发货，每次发货后系统更新已发货 / 剩余发货数量，直至完成全部发货；
  3. 倒计时规则：部分发货状态下，**发货倒计时针对剩余未发货商品继续生效**，超时则触发钉钉群通知采购人员。
  4. 部分发货同步给履约平台后，履约平台需自动拆单，拆单逻辑请看5.22

##### 5.3.3.7 查看详情/查看日志

- **查看详情**：点击后进入采购订单详情页，展示订单全量信息。
- **查看日志**：点击后弹出操作日志弹窗，展示订单所有操作记录；**企业端与供应商端的操作日志互相包含**，可查看对方的操作记录（如采购人员审核、供应商接单），**不记录操作人的 IP 地址和操作设备信息**。

#### 5.3.4 倒计时功能

包含**接单倒计时**和**发货倒计时**，展示规则：精确到时分，超过 24 小时全部换算为小时展示，不显示天，为供应商提供操作时效提醒，超时则触发企业内部钉钉通知，无手动延长时效功能：

##### 5.3.4.1 接单倒计时

- **启动条件**：采购单同步到供应商门户后，系统自动启动。
- **计算规则**：倒计时结束时间 = 接单时效配置 - (当前时间 - 同步门户的时间)，**全部换算为小时，精确到时分**（例：25 小时 30 分、48 小时 15 分），无天单位展示。
- **展示位置**：采购订单列表（对应订单行）、采购订单详情页。
- **提醒功能**：倒计时时间为<=0时，列表显示接单超时红色文字，系统自动发送钉钉群通知，提醒企业采购人员。

##### 5.3.4.2 发货倒计时

- **启动条件**：供应商成功接单后，系统自动启动。**部分发货后倒计时不重置，针对剩余未发货商品继续生效**。
- **计算规则**：倒计时结束时间 = 发货时效配置 - (当前时间 - 同步门户的时间)，**全部换算为小时，精确到时分**（例：25 小时 30 分、48 小时 15 分），无天单位展示。
- **展示位置**：与接单倒计时一致。
- **提醒功能**：倒计时时间为<=0时，列表显示发货超时红色文字，系统自动发送钉钉群通知，提醒企业采购人员，不支持采购人员手动延长接单时效。

#### 5.3.5 SKU条码打印/批量SKU打印

- SKU条码打印/批量SKU打印

  - 单个 SKU 打印1 张条码，条码内容与商品一一绑定
  - 打印前无二次确认，直接唤起浏览器打印预览
  - 多个SKU打印多张条码

  - 条码类型：CODE128（仓库扫码设备通用）
  - 条码下方文字：
    - 内部SKU 
    - 颜色/尺码（颜色去POP拿英文名称）

展示采购订单的全量信息，支持按状态动态显示操作按钮，实现订单信息的一站式查看与操作。

#### 5.4.1 新增字段详细配置

| 字段名称 | 字段类型 | 数据源 / 选项 | 默认值 | 规则说明 |

#### 5.4.2 字段必填校验规则

   1. 新增这三个字段为非必填

#### 5.4.3 字段必填校验规则

1. **校验时机**：供应商状态为待实地验厂、~~验厂评估中、待评级~~、合作中、验厂资料驳回，系统强制校验**备货主体、收款人、税率**三个字段**全部必填**；
2. **拦截提示**：任一字段为空，不允许进入后续环节，前端弹出提示：`请完善供应商基础信息：备货主体、收款人、税率为必填项`；

#### 5.4.4 字段修改权限规则

1. **可修改场景：**供应商状态为待提交、待实地验厂、~~验厂评估中、待评级~~、合作中、验厂资料驳回等所有正常业务环节，均支持随时修改三个字段；
2. **不可修改场景**：供应商状态变为**已淘汰、未验厂取消**，**备货主体、收款人、税率**三个字段全部锁定，不支持任何修改；
3. **修改联动**：修改备货主体时，**税率自动刷新为对应默认值**（香港→0%，广州→13%），可再次手动修改。

#### 5.4.5 开关规则

1. **开关默认状态**：关闭，关闭后供应商无法接收门户采购订单，采购单状态默认待采购，采购单不自动同步到门户。
2. **状态联动**：开关从开启改为关闭时，若该供应商**存在未完结的采购单（待接单 / 已接单 / 部分发货 / 待发货等）**，供应商门户端的未完结订单**仍可正常操作**，无锁定或自动状态变更。

### 5.6 消息通知管理

本次需求核心为钉钉群通知，辅以供应商门户内提示，所有通知均按**X分钟周期统一聚合**，**多供应商的所有相关事件合并为单条通知**发送至钉钉群，无需设置代接人､无需精准标注 SKU､无需撤回误发通知，确保通知简洁､高效；钉钉机器人相关信息读取字典配置 DingTalk_Notify。

**X**分钟读取字典配置DingTalk_Notify.time

#### 5.6.1 通知触发场景

- 供应商发起缺货申请、~~修改数量申请~~（仅通用提醒，不标注具体 SKU）。
- 接单倒计时结束（超时未接单）。
- 发货倒计时结束（超时未发货，含部分发货状态下的剩余商品发货超时）。
- 超时未发货关单通知（超时未发货货，超过X小时）
- 供应商完善资料通知（供应商完善资料，货品池商品待完善/待选品更为为已选品）
- 供应商修改申请审核通知（供应商修改商品信息，触发审核通知）

#### 5.6.2 通知内容规范

通知内容需简洁明了，**将 X分钟周期内所有供应商的相关事件整合为单条通知**，每条事件需包含核心信息：读取字典配置DingTalk_Notify.msg_template，便于采购人员快速查看全量待处理情况并集中处理。

#### 5.6.3 钉钉通知通用规则

1. **推送方式**：直接发送至指定钉钉群，**不支持设置通知代接人**，采购人员自行查看处理。
2. **重复通知**：重复通知:**同一事件**在 X分钟聚合周期内仅聚合 1 次，不重复展示；不同供应商、相同类型的事件统一整合在单条聚合通知内，无单独推送。
3. **误发处理**：系统因数据异常触发错误通知时，**不支持手动撤回**，无需在钉钉群内做更正说明。

#### 5.6.4 通知频率与聚合规则

1. **聚合维度**：**X分钟周期内所有供应商的单类型事件，统一整合为单条钉钉通知**推送，不单独为各供应商生成通知。
2. **推送频率**：按固定时间间隔推送，每**X分钟**统一触发一次钉钉群通知推送，系统在每个周期内自动采集全量未推送事件并完成合并聚合。
3. **事件采集规则**：每个 X分钟聚合周期内，仅采集该周期内**新触发**的各类事件；上一周期已推送的事件，若无新的状态变更，不再重复聚合推送。
4. **空通知兜底**：无新事件触发的 X分钟周期，不生成并发送空通知，系统仅在检测到**有效待推送事件**时，才生成单条聚合通知并推送。

## 六、权限控制要求

1. 采购需求手动触发按钮：做精细化权限控制，仅对企业内部测试人员、特殊业务负责人开放。
2. 供应商门户操作权限：按供应商账号做数据隔离，供应商仅能查看和操作名下的采购订单，无法查看其他供应商的订单信息。
3. 企业内部采购单操作权限：采购人员仅能操作所属负责范围的采购单，审核人员仅能处理所属审核类型的申请。
4. 预警配置权限：仅企业内部系统管理员可配置接单、发货、关单的时效参数。

## 七、数据同步要求

1. **实时性**：供应商门户与订单履约平台的订单状态、操作信息需**实时同步**，确保双方信息一致。
2. **准确性**：采购需求、采购单的数量、价格、库存等核心数据，在跨系统同步时需做校验，避免数据偏差。
3. **异常处理**：若数据同步失败（如采购单同步门户失败、物流信息同步履约平台失败），需标记对应异常状态（如进行中-同步异常），并支持人工重试同步。
